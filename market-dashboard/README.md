## 一、部署 GAS 後端

1. 新建一份 Google 試算表 → 選單「擴充功能 → Apps Script」。
2. 把 `Code.gs` 全部內容貼上，覆蓋預設程式碼；再按左側「檔案 ＋ → 指令碼」新增一個名為 `Macro` 的檔案，貼上 `Macro.gs`。兩個檔案都要存檔。
3. 上方函式選單選 `testQuotes` → 執行，第一次會要求授權（試算表、外部連線），允許後在「執行紀錄」看到報價 JSON 即代表正常。
4. 右上「部署 → 新增部署作業」→ 類型選「網頁應用程式」
   - 執行身分：**我**
   - 存取權：**所有人**
5. 複製產生的網址（`https://script.google.com/macros/s/……/exec`）。

> 之後修改 Code.gs，要到「部署 → 管理部署作業 → 編輯 → 版本選『新版本』」才會生效，網址不變。

## 二、設定前端

二擇一：
- 把網址貼到 `app.js` 第 6 行 `const API_URL = '';`
- 或打開網頁後，在登入頁下方「後端網址設定」貼上並儲存（存在瀏覽器）。

直接雙擊 `index.html` 即可使用；也可以放到 GitHub Pages / Netlify 等靜態空間。

## 三、試算表結構

- **Account** 工作頁：A 帳號｜B 密碼｜C 建立時間｜D 審核狀態
  - D 欄：空白＝待審核、「通過」、「拒絕」、「停用」。只有「通過」的帳號與管理員（`michael`，在 Code.gs 的 `ADMIN_ACCOUNT` 設定）可以登入。
  - 管理員在網頁「⚙ 設定 → 帳號審核」操作，或直接在 D 欄填「通過」（最慢 5 分鐘生效）。一般帳號的個人工作頁在審核通過、第一次登入時才建立。
  - B 欄存的是「隨機鹽 + SHA-256 雜湊」，不是明碼（即使試算表外流也無法得知原密碼）。
- **<帳號名稱>** 工作頁（註冊時自動建立）：
  - A:E 監控清單：類別｜代碼｜顯示名稱｜資料來源｜新增時間（列的順序 = 畫面上的順序）
  - G:H 個人設定：設定項目｜值（例如 `cardOrder` = 區塊排列順序）
  - 可直接在試算表編輯顯示名稱、調整列順序，重新整理網頁即生效。刪除標的時請只清除 A:E 該列內容或用網頁刪除，不要刪整列（會動到 G:H 設定）。

| 區塊 | 來源 | 更新方式 | 備註 |
|---|---|---|---|

休市時來源會回傳最後成交價，畫面就停在最後價格；連線失敗時也保留上一次報價。

### 配額注意
GAS 免費帳號 UrlFetch（向外部網站抓資料）每日上限 **20,000 次**（Workspace 帳號 100,000 次）。市場監控頁上方的「今日 API 呼叫」會即時顯示今天已用次數（所有使用者、分頁合計，台北時間每日歸零），用量達 70% 變黃、90% 變紅。

預設更新頻率為 **30 秒**（可在畫面右上自行調整，選擇會記在瀏覽器）。**設定資料中繼站（見「十五」）後，報價與走勢完全不用 GAS 額度**；沒有中繼站時，單人、預設清單估算：

| 更新頻率 | 每天開 8 小時 | 24 小時都開 |
|---|---|---|
| 30 秒 | 約 2,100 次 | 約 6,200 次 |
| 10 秒 | 約 6,000 次 | 約 17,800 次 |

虛擬貨幣直連 Binance 不佔額度。只有停留在市場監控頁、且分頁在前景時才更新；切到其他頁或背景會完全停止。每個區塊可按 ⏸ 停止更新，工具列「⏸ 全部停止」一次停止全部（設定存在帳號 `pausedCats`）。多分頁/多裝置同時開會倍增用量。

## 六、走勢圖與編輯

- **當日走勢小圖**：每列價格左側。台股/國外/指數/匯率為當日 5 分線（後端快取 2 分鐘、每 3 分鐘更新）、虛擬貨幣為近 24 小時 15 分線；虛線為昨收（基準），尾端會接上即時價格。
- **點任一標的開啟走勢圖**：
  - 週期：日 / 週 / 月；範圍：3月 / 6月 / 1年 / 3年（預設）/ 全部
  - 圖型：K 線 / 折線；成交量可開關（匯率等無成交量的標的會自動停用）
  - 滑鼠滾輪縮放、按住拖曳左右移動；手機雙指縮放。後端多抓了更早的歷史，往左拖可看超過 3 年
  - 「📈 技術分析」：SMA5/10/20/60/120 疊在主圖，KD(9,3,3)、MACD(12,26,9) 各一個副圖，每項都可勾選開關；副圖之間的分隔線可上下拖曳調整高度
  - 圖表設定會記在瀏覽器，下次打開沿用
- **✎ 編輯**（工具列）：拖曳標的調整順序、拖曳區塊標題（⠿）移動整個區塊、按紅色 × 刪除；排序會存回試算表，換電腦登入也一樣。

> 更新 Code.gs 後記得「管理部署作業 → 編輯 → 版本：新版本 → 部署」，否則新功能（走勢、排序）會出現「未知的 action」錯誤。

**編輯版面**：按「✎ 編輯版面」後可拖曳字卡標題調整順序、設定每張字卡寬度（1/3～全寬）、取消「顯示」隱藏字卡（隱藏的不抓資料，省額度）；版面存在試算表個人設定 `macroLayout`，換電腦也一樣。「還原預設」可回到原始排列。

**載入穩定性**：同時最多送 4 個請求（避免 GAS 同時執行數過多、證交所限流）；某區塊失敗會自動重試（5→10→20→30→60 秒，10 次後每 5 分鐘），直到狀態燈轉綠；只在停留此頁且分頁在前景時重試。後端在來源失敗時會回傳最近 6 小時內成功的資料（字卡時間顯示「資料 hh:mm」並以黃字倒數重試）。

**瀏覽器快取**：每個區塊成功載入後會存一份在瀏覽器（localStorage，依帳號分開，3 天內有效）；重新整理網頁後進入此頁會先立即顯示上次的資料（字卡時間顯示「上次資料 hh:mm」），再在背景更新。

每次開啟約用 35–45 次外部請求（台股類股的歷史收盤每天第一次較多），快取期間內重開幾乎不耗額度。

注意：
- FOMC 機率由期貨價格推算，與 CME FedWatch 網站可能有些微差異（期限溢酬、資料時間不同）。
- 證交所信用交易與法人資料於交易日晚間公布，盤中看到的是前一交易日。
- 上櫃資料：櫃買中心沒有歷史區間查詢（OpenAPI 只有當日或當月），只能逐日抓，而且信用交易每天的回應含全部個股（約 107KB）。後端會把查過的日子永久存在 Apps Script 的「指令碼屬性」，之後只補新日期。
  - **切換「上櫃」時只先補最近 8 天**（一批平行抓完，實測信用交易約 1.3 秒、法人約 0.5 秒），馬上顯示。
  - 歷史還沒補齊時，前端在背景呼叫 `margin_otc_fill`／`inst_otc_fill` 一次補較多天（信用交易 60 天約 10–20 秒、法人 30 天約 2 秒），完成後字卡自動更新；信用交易需要 120 個交易日，之後幾次開啟陸續補滿。補滿後每次只檢查最近幾天。
  - 櫃買指數疊圖：FinMind 歷史（帶 token）＋櫃買中心本月每日指數補最新幾天。
  - 上櫃資金流向估算金額的收盤價改用精簡版 `tpex_mainboard_quotes`（約 0.36MB，以前用的完整版近 5MB）。
- **PDF 報告**：工具列「📄 產出 PDF 報告」，見「十三之二」。
- 上市資料先用 FinMind（一次取得半年），失敗時改用證交所逐日查詢並永久保存（第一次約 17–20 個交易日，之後逐次補齊），面板下方的「來源」會寫出原因。建議到 finmindtrade.com 免費註冊，把 token 填到指令碼屬性 `FINMIND_TOKEN`（不要寫在 Macro.gs 裡），成功率會高很多。
- FinMind 免費 API 有每小時次數限制，若 Google 伺服器 IP 被限流，會自動改用證交所（只顯示最新一日）。

## 八、個股研究

輸入台股代號（2330）、美股代號（NVDA），或其他市場（7011 JP、0700 HK），顯示完整檔案：
走勢與成交量（K 線、MA20/60/120/240）、技術分析（RSI、KD、MACD、乖離）、歷史波動度（HV20/HV60 與百分位）、
估值（本益比在自身歷史的百分位帶）、成長與獲利（單季 EPS、營收年增、毛利率／營益率／淨利率）、月營收（台股）、
籌碼（台股：法人、外資持股、融資；美股：機構持股、內部人持股、放空比例、回補天數）、相對強弱（對加權指數／S&P 500）、分析師目標價與評等、股利、公司簡介。

每個面向依固定規則給出判斷（多頭／空頭、偏高／偏低、成長／衰退…），判斷依據寫在各字卡下方；各面向彼此獨立、不加總成買賣建議。
資料：
- 台股：FinMind（token 放在指令碼屬性 `FINMIND_TOKEN`）＋證交所＋Yahoo。
- 美股：分三層，任何一層失敗都不影響其他——
  1. Yahoo 財報／估值時間序列（**不需要認證**）：單季與年度財報、市值、本益比、預估本益比、股價淨值比、PEG；
  2. Nasdaq（**不需要認證**，僅美國上市股票）：公司簡介、產業、殖利率、機構持股、放空與回補天數、分析師目標價與買進／持有／賣出家數、下次財報日；
  3. Yahoo 完整資料（quoteSummary，**需要 cookie＋crumb 認證**，Google／Cloudflare 主機常被拒絕）：抓得到時優先使用，另含員工數、內部人持股、近期評等異動。
  舊版只用第 3 層，認證失敗時市值、本益比、成長與獲利、籌碼、公司簡介都會空白。Beta 抓不到時以近一年日報酬對 S&P 500 自行計算；放空比例改用 Nasdaq 時以「占總股數」顯示。
- 其他市場（日、港、韓等）：沒有 Nasdaq 資料，簡介、分析師、籌碼只在 Yahoo 認證成功時顯示；財報與估值仍有。

## 九、選股篩選器（需先啟用一次）

1. 在 Apps Script 新增指令碼檔 `Research`、`Screener`，貼上對應的 .gs 內容並重新部署。
2. 在編輯器上方函式選單選 **setupScreener** → 執行（會要求「管理觸發條件」等授權）。
3. 後端會開始每 5 分鐘補一段歷史（上市＋上櫃約 2,300 檔、250 個交易日），約 20–40 分鐘完成後自動停止；之後每天 21:40 自動抓當日資料並重算。
   資料存在試算表隱藏工作頁 `_daily`（每日快照）與 `_screen`（算好的篩選表），請勿手動修改。

## 十四、效能與穩定性

- **外部來源斷路器**：某個來源（常見是證交所限流或封鎖 Google 主機）連不上、或單次超過 12 秒，就暫停該來源 3 分鐘，期間直接改用備援或舊資料，不再讓每個請求都等到逾時；3 分鐘後自動恢復嘗試。在 Apps Script 執行 `resetHosts` 可立即解除所有暫停。
- **台股報價備援**：證交所即時報價（MIS）暫停或沒回資料時，台股改抓 Yahoo（市場監控狀態列會提示「台股暫用 Yahoo 報價」）。
- **批次請求不再重複等待**：以前批次中有一個網址連不上，會把整批逐一重抓，卡住的來源要再等一次逾時；現在只暫停那個來源，其他照常。
- **連線診斷**（設定頁）：實測各資料來源的回應時間、列出暫停中的來源、近 1 小時各來源的耗時與失敗次數、本頁每次請求的總耗時與後端耗時，並給出判斷。慢的時候先看這裡。
- **選股篩選器修正**：以前證交所連線失敗時，會把交易日永久標成「非交易日」，造成資料缺漏、排程反覆向證交所補資料。已修正；可在 Apps Script 執行一次 `screenerRecheckHolidays` 清除過去可能誤標的日期（下次排程自動重新確認）。
- 類股指數歷史在證交所失敗時不再被快取成「非交易日」6 小時。
- 前端逾時：報價與走勢小圖 30 秒（下一輪再抓），其他 90 秒。

- **對外請求計數不再上鎖**：以前每次對外請求都要拿全域鎖、寫一次指令碼屬性；選股排程（每天 21:40、首次建置時每 5 分鐘）佔用鎖的 4–5 分鐘內，使用者每個請求都會多等 3 秒，新增標的、排序也可能逾時失敗。現在只在記憶體累計、每次執行結束寫入一次。
- **使用者的寫入操作改用試算表的鎖**（註冊、審核、排序、投資組合、ETF 快照），不會被選股排程卡住。
- **背景載入排隊**：總經、財金日曆的字卡與走勢小圖、投資組合歷史資料，全站同時最多 4 個請求；使用者直接操作（新增、儲存、查詢、報價）不排隊，優先處理。
- **前端請求逾時 90 秒**：後端卡住時不會無限等待，會顯示錯誤或自動重試。
- **選股篩選器**：後端直接傳壓縮資料由瀏覽器解壓，並存一份在瀏覽器；資料沒更新時不重傳，重新整理網頁後立即顯示。
- **ETF 完整持股快照**改存在 `_etfh` 工作頁、只讀單一 ETF 的列（舊資料第一次查詢時自動搬移），`_etf` 維持小而快。
- 新增台股標的時沿用解析代號時抓到的報價，不再重抓。

## 十五、資料中繼站（Cloudflare Workers，強烈建議設定）

**為什麼需要**：所有資料原本都由 Google Apps Script 代抓，有三個先天限制：
1. Google 主機的 IP 很多人共用，Yahoo、證交所常常限流或封鎖，造成「抓很久」或「只有框架沒有資料」。
2. 一般 Google 帳號每天只有 20,000 次對外請求，用完後所有經後端的資料都抓不到（約 24 小時恢復）。實際案例：某天用到 13,621 次後於晚上用完，之後總經、日曆、ETF 全部失敗。
3. 每次請求都要等 Apps Script 啟動（1–3 秒）。

設定中繼站後：
- **市場監控與投資組合**：報價、當日走勢、K 線、投資組合的歷史價格／配息／分割，全部由瀏覽器直接經中繼站抓，完全不經 Google。
  實測（後端完全故障時）：6 檔報價 0.5 秒內出現、K 線 0.25 秒、投資組合 4 檔歷史資料 2 秒。
  證交所與 Yahoo 分開抓、各自逾時，先回來的先顯示；證交所慢時台股 8 秒內改用 Yahoo，之後 3 分鐘直接走 Yahoo。
- **總經與財金日曆**：大部分字卡由瀏覽器資料引擎計算（見「十六」），也不經 Google。
- **後端其他資料**（ETF、個股研究、信用交易、法人…）對 Yahoo、證交所等網站的請求也經中繼站轉送，不會因 Google 主機被擋而失敗。
- 中繼站有邊緣快取（報價 5 秒、走勢 15–30 秒、Nasdaq 過去日期 6 小時…），多人同時看同一檔只向來源抓一次；免費方案每天 100,000 次。
- 中繼站故障時自動退回原本的方式，不會比沒設定更差。
- 中繼站只轉送白名單內的網站，且必須帶正確的 KEY，不會被別人當成公開代理。

**設定步驟（約 5 分鐘）**：
1. 到 https://dash.cloudflare.com 註冊免費帳號（只需 Email）。
2. 左側「Workers & Pages」→「Create」→「Create Worker」→ Worker name 改成 `mw-proxy`（「Protect with Cloudflare Access」保持關閉）→「Deploy」。
3. 部署完成後按右上「Edit code」，Ctrl+A 刪掉預設內容，把 `worker.js` 全部貼上 → 右上「Deploy」。
4. 回到 Worker 頁面 →「Settings」→「Variables and Secrets」→「Add」：Production 打勾、Key 填 `KEY`、Value 填自訂英數密碼、**Secret 打勾** →「Add variable and deploy」。
5. 測試：瀏覽器打開
   `https://mw-proxy.你的帳號.workers.dev/?key=你的KEY&url=https%3A%2F%2Fquery1.finance.yahoo.com%2Fv8%2Ffinance%2Fchart%2F2330.TW%3Frange%3D1d`
   看到 `{"chart":{"result":[...` 就成功；`forbidden` 代表 KEY 不對；`Hello World!` 代表程式還沒換成 `worker.js`。
6. Apps Script →「專案設定（齒輪）」→「指令碼屬性」→「新增指令碼屬性」：`PROXY_URL` = Worker 網址（結尾不要加 `/`）、`PROXY_KEY` = 第 4 步的密碼 → 儲存。
7. 網頁登出再登入 → 到「設定 → 連線診斷」，應顯示「資料中繼站：已啟用」，「本頁最近的請求」會出現「直連 …」紀錄。

**更新 worker.js 時**：Cloudflare → `mw-proxy` →「Edit code」→ 全選貼上新版 →「Deploy」。KEY 不用重設。
（2026-10 版的 worker.js 新增：自動跟隨轉址、預檢快取一天、財政部與 FRED API 白名單、Nasdaq 過去日期快取 6 小時；**期貨專區**另需要期交所與 CFTC 白名單、期交所即時行情的 POST 轉送、Big5 編碼處理。之前貼過舊版的請重新貼一次。）

## 十六、資料架構與完整設定清單

### 16.1 各頁資料走哪條路

| 頁面／功能 | 有中繼站時 | 沒有中繼站時 |
|---|---|---|
| 市場監控：報價、當日走勢、K 線 | 瀏覽器 → 中繼站 → 來源（不經 Google） | Google 後端代抓 |
| 投資組合：報價、歷史價格／配息／分割 | 瀏覽器 → 中繼站（不經 Google） | Google 後端代抓 |
| 總經：跨資產、新聞、類股熱力圖、美債曲線、美國經濟數據、FOMC、資金流向 | **瀏覽器資料引擎**（不經 Google） | Google 後端 |
| 總經：信用交易、三大法人、台灣景氣 | Google 後端（經中繼站轉送） | Google 後端 |
| 財金日曆：全部字卡 | **瀏覽器資料引擎**（不經 Google） | Google 後端 |
| 期貨專區：全部字卡 | **瀏覽器資料引擎**（CFTC 由瀏覽器直連，不經 Google） | Google 後端 |
| ETF 專區、個股研究、選股篩選器、回測 | Google 後端（經中繼站轉送） | Google 後端 |
| 虛擬貨幣 | 瀏覽器直連 Binance | 瀏覽器直連 Binance |

信用交易、法人要逐日累積歷史（存在指令碼屬性），ETF 申贖與持股快照存在試算表，台灣景氣要解壓 ZIP，所以留在後端；這些在後端也已做減量優化（見 16.4）。

### 16.2 瀏覽器資料引擎（`engine.js`、`engine-worker.js`）

- 在瀏覽器的背景執行緒（Web Worker，不會讓畫面卡住）直接載入**同一份**後端程式（`Code.gs`、`Macro.gs`、`Calendar.gs`、`Futures.gs`），只把 Google 專屬服務換成瀏覽器版本：對外請求一律經中繼站、快取放記憶體、設定放 localStorage。
  計算邏輯只有一份，前後端結果一致；以後修改 .gs，瀏覽器與後端同時生效。
- 同時 3 個背景執行緒，各算一張字卡。需要逐日查很多網址的字卡（經濟日曆 19 天、美股財報 10 天），先由引擎列出網址、主執行緒同時抓 6 個，再交給引擎計算。
  實測（完全沒有快取時）：跨資產 1.0 秒、新聞 1.8 秒、類股熱力圖 0.4–2.7 秒、FOMC 1.8 秒、資金流向 2.6 秒、美債曲線 3.1 秒、財報日曆 0.5 秒、市場重要日期 0.8 秒、除權息 1.1 秒、美股財報 5.5 秒、經濟日曆 7.8 秒。
- 引擎失敗（例如某個來源暫時沒回應）會自動改走後端，後端還有 6 小時內的備援資料；網站沒有引擎時也照常運作。
- **有些網站擋 Cloudflare 的主機**（資料中心 IP），所以不是每個網站都經中繼站：
  - 證交所網站（www.twse.com.tw）允許瀏覽器跨站讀取，改由瀏覽器**直接連**（用使用者自己的網路；實測除權息從 19 秒降到 1.7 秒），直連失敗才經中繼站。
  - Forex Factory 擋 Cloudflare 但不擋 Google：經中繼站抓不到時，改請後端代抓（`relay`，後端快取 30 分鐘，幾乎不耗額度）；後端自己抓時也直接連、不經中繼站。
  - 後端經中繼站被拒（403／429／5xx）的請求，會自動改由 Google 直連再試一次。
- **使用條件**：已設定中繼站，且網頁以 **http/https 開啟**（例如 GitHub Pages）。直接雙擊 `index.html`（網址列是 `file://`）時瀏覽器不允許載入背景程式，這些字卡會自動改走後端。
- **必須和網頁一起上傳**：`engine.js`、`engine-worker.js`、`Code.gs`、`Macro.gs`、`Calendar.gs`、`Futures.gs`。FinMind token 只放在指令碼屬性（見 16.3 第 3 點），因為 .gs 會被瀏覽器下載。

### 16.3 完整設定清單（照順序做一次）

1. **Cloudflare 中繼站**：見「十五」。已設定過的話，把最新版 `worker.js` 重新貼上並 Deploy。
2. **Apps Script 程式**：把以下檔案換成最新版（沒有的用「檔案 ＋ → 指令碼」新增）：
   `Code.gs`、`Macro.gs`、`Calendar.gs`、`Futures.gs`、`Etf.gs`、`Screener.gs`、`Research.gs`、`Portfolio.gs`
   →「部署 → 管理部署作業 → 鉛筆 → 版本：新版本 → 部署」（網址不變）。
3. **指令碼屬性**（專案設定 → 指令碼屬性）：

   | 屬性 | 值 | 用途 |
   |---|---|---|
   | `PROXY_URL` | `https://mw-proxy.你的帳號.workers.dev` | 資料中繼站網址 |
   | `PROXY_KEY` | Cloudflare 設定的 KEY | 中繼站密碼 |
   | `FRED_KEY` | FRED 免費 API 金鑰（選用，建議） | 美國經濟數據改走 FRED 官方 API |
   | `FINMIND_TOKEN` | FinMind token（選用，建議） | 台股信用交易、法人、個股研究 |

   設好 `FINMIND_TOKEN` 後，把 `Macro.gs` 裡 `const FINMIND_TOKEN = '…'` 改成 `''` 再部署，避免 token 隨 .gs 上傳到網頁而外流。
   其他已存在的屬性（`etfTrack`、`fetchUsage`、`otc_*`、`tse_*`、`ffw_*`、`ysessLast`、`fredbk_*` 等）是程式自己用的，不要刪改。
   屬性名稱大小寫要完全一樣；加完不用重新部署，但網頁要重新整理一次，瀏覽器引擎才會拿到新的 `FRED_KEY`。
4. **FRED API 金鑰**（建議）：到 https://fredaccount.stlouisfed.org 註冊 → 「API Keys」→「Request API Key」→ 複製 32 碼金鑰填到 `FRED_KEY`。
   FRED 網站對程式請求常常很慢或沒回應（實測多次逾時），官方 API 則穩定；沒填時美國經濟數據退回網站下載。美債殖利率曲線已改用**美國財政部**官方資料，不需金鑰。
5. **網頁檔案**（上傳到 GitHub Pages 等，或放在同一資料夾）：
   `index.html`、`style.css`、`app.js`、`engine.js`、`engine-worker.js`、`panels.js`、`macro.js`、`cal.js`、`futures.js`、`report.js`、`research.js`、`screener.js`、`etf.js`、`portfolio.js`、`backtest.js`、`help.js`、`settings.js`，以及 `Code.gs`、`Macro.gs`、`Calendar.gs`、`Futures.gs`（瀏覽器引擎用）。
6. **在 Apps Script 執行一次**：`screenerRecheckHolidays`（清除舊版誤標的非交易日）。
7. **排程**（Apps Script 左側鬧鐘「觸發條件」）：`screenerDaily`、`etfHoldDaily` 保留；`screenerBackfill` 是選股器補歷史資料用，補完會自動刪除。若 Google 額度吃緊可先刪除它，之後再執行一次 `setupScreener` 重建。
8. **確認**：網頁登出再登入 →「設定 → 連線診斷」：
   - 「資料中繼站：已啟用」、「瀏覽器資料引擎：已啟用」
   - 「本頁最近的請求」出現「直連 …」（市場監控、投資組合）與「瀏覽器 …」（總經、財金日曆）紀錄
   - 按「實測各資料來源」，各來源應為綠色「正常」

### 16.4 後端減量優化（ETF 等仍在後端的功能）

- ETF 申贖快照：一天只寫一次（2 小時內不重複），歷史從快取讀；以前每次開啟 ETF 總覽、美股 ETF 都要整張讀寫工作頁。實測重新計算時工作頁讀取 0 次、寫入 0 次。
- 個別 ETF：只讀需要的那一格（以前每次整張讀取約半 MB 的快照）；完整持股快照另存 `_etfh` 工作頁。
- 總經、日曆的經濟數據：來源回傳空資料時不再當成成功（以前會顯示「只有框架沒有資料」並被快取），改用備援資料並自動重試。

### 16.5 疑難排解

| 狀況 | 原因與處理 |
|---|---|
| 「連線診斷」顯示 Google 額度已用完 | 經後端的資料約 24 小時內恢復；有中繼站時市場監控、投資組合、總經大部分、財金日曆不受影響 |
| 「瀏覽器資料引擎：未啟用（file://）」 | 網頁是直接開檔案，改放 GitHub Pages 等網站即可 |
| 「瀏覽器資料引擎：無法啟動」 | `engine-worker.js`、`Code.gs`、`Macro.gs`、`Calendar.gs`、`Futures.gs` 沒有和網頁一起上傳 |
| 期貨專區的台灣字卡很慢或失敗 | `worker.js` 還是舊版（沒有期交所白名單與 POST 轉送），改走後端而變慢：重新貼上最新版並 Deploy；後端也要新增 `Futures` 並部署 |
| 「產出 PDF 報告」只跳出列印視窗、沒有新分頁 | 瀏覽器擋住彈出視窗：在網址列右側允許此網站；列印時「目的地」選「另存為 PDF」、勾選「背景圖形」 |
| 上櫃信用交易／法人只有幾天 | 正在背景補齊歷史（完成後自動更新）；信用交易 120 個交易日需要幾次開啟陸續補滿 |
| 美國經濟數據常常失敗 | 多半是沒設定 `FRED_KEY`（FRED 網站對程式請求常常沒回應）。字卡會寫出原因；「連線診斷」會顯示金鑰是否已設定，按「實測」會測「FRED 官方 API」 |
| 美股個股研究的市值、本益比、籌碼、簡介是空的 | 更新 `Research.gs`、`Calendar.gs` 並部署新版本（新版不再依賴 Yahoo 認證）；日股、港股等沒有 Nasdaq 資料，簡介與籌碼仍可能空白 |
| 台股報價顯示「暫用 Yahoo 報價」 | 證交所即時報價暫時很慢或擋連線，3 分鐘後自動改回證交所 |
| 中繼站回 `forbidden` | `PROXY_KEY` 與 Cloudflare 的 KEY 不一致 |
| 更新 .gs 後網頁沒變 | Apps Script 要「部署新版本」；瀏覽器引擎會自動抓新版 .gs，若仍是舊的請強制重新整理（Ctrl+F5） |
