# 每日市場報告：分析邏輯與產出規則

這份文件是每日報告的底層規則。每次產出報告前都要先完整讀過，不能只憑印象。
規則有修改時直接改這份檔案，並在最下方「修訂紀錄」加一行。

- 網站：<https://finatticus.github.io/structuredproductanalysis/daily/>
- Repo：<https://github.com/Finatticus/structuredproductanalysis>（本機 `C:\Users\User\Desktop\news` 是它的 sparse checkout，只追蹤 `daily/`，不要動 repo 裡其他檔案）
- 讀者：一位在台灣、有金融背景的投資人。要的是「看完就掌握全世界大小事，並知道短中長期該怎麼想」。
- 語言：繁體中文（台灣用語）。漲用紅、跌用綠（台灣慣例）。

---

## 一、最高原則

1. **即時性優先。** 市場每天都在變。所有數字都必須是這一次執行時重新查到的，不可沿用昨天報告的數字當成今天的，更不可用模型記憶中的數字。模型的知識截止日遠早於現在，凡是價格、利率、人事、政策，一律以搜尋結果為準。
2. **每個數字都要有出處與時間。** 報告內的行情表要標「資料時間」；文中的關鍵事實要能對應到文末來源清單的連結。
3. **查不到就說查不到。** 寧可寫「今日尚未公布」「各來源不一致（A 說 x、B 說 y）」，也不要補一個看起來合理的數字。絕對不可編造數字、引述或連結。連結必須是實際在搜尋結果或抓取頁面看到的 URL。
4. **事實與判斷分開。** 「發生了什麼」和「我怎麼看」要讓讀者分得出來。機率一律註明是主觀估計。
5. **觀點要連續、改變要交代。** 每天的短中長期看法都要和前一天比較：維持、上修或下修，並說明是哪個新資訊造成的。沒有新資訊就不要為了變而變；有重大新資訊就不要為了一致而硬撐。
6. **正反並陳。** 每個時間尺度都要寫出「支持」與「反對」的理由，以及「什麼情況會讓我改變看法」。
7. **不是投資建議。** 報告結尾固定附免責聲明；可以給思考框架，不給個人化買賣指示。

## 二、每日作業流程

### 步驟 0：讀檔（必做）

1. 讀本檔 `daily/RULES.md`。
2. 讀 `daily/state/view-log.md`（觀點與關鍵價位的延續紀錄、待追蹤事件）。
3. 讀最近一到兩份報告 `daily/reports/YYYY-MM-DD.html`，沿用其版型與 class（不要重新發明版面）。
4. 用系統時間確認今天日期、星期，以及各市場目前是開盤前、盤中還是收盤後。

### 步驟 1：蒐集資料（全部重新查）

早上 8 點（台北）這個時間點的狀態：美股剛收盤（台北時間清晨 5–6 點）、歐股前一晚收盤、台股與亞股是「昨日收盤、今日未開盤」。週一早上則是美股上週五收盤加上週末消息。

資料量大，建議同時開 4–5 個研究子代理平行蒐集，每個子代理把結果寫成 Markdown 檔，並要求每個數字附來源連結與日期。分工如下：

| 區塊 | 必查內容 |
| --- | --- |
| 美國 | 四大指數、費半、VIX、類股、重點個股；美債殖利率；聯邦基金期貨定價；聯準會官員談話；經濟數據（實際/預期/前值）；財報；政治與政策；期貨盤後走勢 |
| 台灣 | 加權、櫃買、成交值、漲跌家數；三大法人；台指期（含夜盤）與外資未平倉；選擇權 P/C；融資融券；新台幣；權值股與族群；均線位置；政策（國安基金、金管會、央行）；基本面數據；法人觀點；台積電 ADR |
| 亞太 | 日本、南韓、中國、香港、印度、東南亞、澳紐：指數、匯率、央行、數據、政策、新聞 |
| 歐洲與其他 | 歐股、英股、ECB/BoE；俄烏、中東、美中；拉美、中東、加拿大；國際機構（IMF、OPEC+、G20） |
| 跨資產與產業 | 美元指數與主要匯率；全球殖利率與信用利差；原油、天然氣、黃金、銅、農產品、運價；比特幣；資金流向與情緒；AI/半導體產業鏈；各大行觀點 |

來源優先順序：官方（證交所、期交所、央行、主計總處、Fed、BLS、ECB）＞通訊社與主流財經媒體（Reuters、Bloomberg、CNBC、WSJ、FT、Nikkei、中央社、經濟日報、工商時報、鉅亨網、MoneyDJ）＞其他。部落格、內容農場、AI 生成的整理站只能當線索，不能當唯一依據。

### 步驟 2：查核

- 關鍵數字（指數收盤、漲跌幅、法人買賣超、利率、匯率）至少兩個獨立來源一致才直接寫；只有單一來源就標「單一來源」。
- 自己驗算：漲跌點 ÷ 前收 = 漲跌幅；距高點幅度；價位距離百分比。算出來不合就回頭查。
- 檢查日期：很多搜尋結果是舊聞。確認每則新聞的發布日在 48 小時內（行事曆、背景資料除外）。
- 檢查前一天報告的「待確認事項」，有新資料就更正，並在「資料限制」區塊寫明更正了什麼。

### 步驟 3：分析（見第三節框架）

### 步驟 4：寫報告

- 檔名 `daily/reports/YYYY-MM-DD.html`，以最近一份報告為版型，共用 `../assets/report.css` 與 `../assets/report.js`。
- 內容結構見第四節。

### 步驟 5：更新索引與紀錄

1. 在 `daily/reports.js` 陣列**最前面**加一筆（date、weekday、edition、headline、summary、global/taiwan 的 short/mid/long 立場、taiex、spx）。
2. 更新 `daily/state/view-log.md`：加上今天的觀點、機率、關鍵價位、變更理由；更新「待追蹤事件」。

用 5 行以內告訴使用者：今天的一句話結論、觀點是否有變、報告連結、以及任何沒查到或不確定的重要資料。

## 三、分析框架

### 3.1 時間尺度定義

| 尺度 | 期間 | 主要驅動 | 判斷依據 |
| --- | --- | --- | --- |
| 短期 | 1–2 週 | 事件、籌碼、情緒、技術面 | 行事曆上的催化劑、期貨與選擇權部位、融資、均線與缺口、波動率 |
| 中期 | 1–3 個月 | 央行政策路徑、財報與獲利修正、資金流向、估值調整 | 利率期貨定價、獲利預估修正方向、外資動向、信用利差 |
| 長期 | 6–18 個月 | 景氣循環、產業趨勢、獲利成長、估值水位、結構性風險 | GDP 與獲利成長預估、資本支出週期、債務與融資條件、政策與地緣結構 |

### 3.2 每個尺度都要回答的六個面向

1. **政策與利率**：央行在升息、降息還是觀望？市場定價與央行說法有沒有落差？財政政策、監管政策的方向？
2. **基本面與獲利**：經濟數據是在加速還是減速？企業獲利預估是上修還是下修？
3. **估值**：本益比相對歷史與相對利率在什麼位置？已反映多少好消息或壞消息？
4. **資金與籌碼**：誰在買、誰在賣？槓桿高不高？（台股必看：外資現貨與期貨、投信、融資、新台幣）
5. **情緒與技術**：恐慌還是貪婪？關鍵均線與價位在哪？成交量說了什麼？
6. **事件與地緣**：接下來行事曆上有什麼？尾部風險是什麼？

### 3.3 立場的表示方式

五級立場：**偏多／中性偏多／中性／中性偏空／偏空**。每個立場都要附：

- 一句話理由
- 信心程度（高／中／低）
- 與前一日相比：維持、上修、下修（及原因）
- 情境表：至少三種情境（樂觀／基本／悲觀），各有觸發條件、可能區間、主觀機率（合計 100%）
- 翻轉條件：「看到什麼我會改變看法」

機率是主觀估計，不要寫得像模型算出來的。前後兩天機率變動要有理由。

### 3.4 利空／利多的分類法

遇到重大事件，先分類再判斷消退速度：

- **事件面**（人事、單一公司、單一數據）：通常幾天到幾週內被消化。
- **政策面**（監管、關稅、選舉結果）：影響漸進、持續數月。
- **資金面**（利率、流動性、信用、去槓桿）：最慢，最影響估值。
- **基本面**（需求、獲利、景氣）：最重要，決定長期方向。

多層疊加時要分開寫，不要混成一句「利空衝擊」。

### 3.5 台股專用檢查表

每天都要更新這些項目，並和前一天比較：

- 加權指數相對各均線（5/10/20/60/120/240 日）的位置；距歷史高點與近期低點的幅度
- 外資現貨買賣超（當日、連續天數、當月累計）
- 外資台指期淨未平倉（口數與增減）；注意投信多單多為 ETF 避險性質，不能把外資空單全當成看空
- 融資餘額與增減、維持率、是否有斷頭賣壓
- 新台幣匯率與外資匯出入；央行是否進場
- 台積電股價、ADR 溢價、占大盤權重與對指數的貢獻點數
- 台指期夜盤與逆價差
- 政策：國安基金、限空措施、金管會與央行發言
- 止穩訊號清單（幾項成立）
- 關鍵價位表（壓力、支撐、意義、距離）

### 3.6 全球專用檢查表

- 美股：四大指數與費半、VIX 水位與期限結構、類股輪動（防禦 vs 成長）、市場寬度
- 利率：美債 2 年／10 年、殖利率曲線、聯邦基金期貨對未來兩次會議的定價
- 美元與主要匯率；日圓（套利交易風險）；人民幣
- 信用：投資級與高收益利差、有沒有壓力事件
- 商品：原油、黃金、銅（景氣訊號）
- 產業主線：目前是 AI 資本支出週期。每天追蹤雲端業者資本支出、輝達／台積電／記憶體、融資條件、監管
- 跨市場連動：美股 → 亞股 → 台股的傳導是否如常，或出現背離

### 3.7 常見錯誤（要避免）

- 把國安基金進場日當成最低點
- 把單日反彈當成趨勢反轉（要看外資是否連續回補）
- 直接套用歷史前例而不比較當時的利率環境與事件性質
- 只引用看多或只引用看空的機構
- 把二手整理站的數字當成原始資料
- 把「市場預期」寫成「已經發生」
- 忽略時區：美股日期與台北日期差一天，財報「週二盤後」是台北週三清晨

## 四、報告內容結構（固定順序）

1. **頁首**：日期、星期、版次、資料截止時間（台北時間）
2. **今日重點**：一句話結論＋3–5 個最重要的事（每個都要有「所以呢」）
3. **觀點總表**：全球與台灣 × 短／中／長期，立場、信心、較昨日變化、一句話理由
4. **行情總覽**：股市、利率、匯率、商品、加密資產表格（收盤、漲跌、漲跌幅、備註；標資料時間）
5. **全球市場**：昨夜今晨發生什麼 → 短期 → 中期 → 長期（各含六面向重點、情境表、翻轉條件）
6. **台灣市場**：盤勢與籌碼 → 關鍵價位 → 短期 → 中期 → 長期 → 止穩訊號清單
7. **主題深入**：當天最重要的 1–3 個主題（例：輝達財報、聯準會、AI 資本支出）做較完整的分析
8. **行事曆**：未來一到兩週的數據、央行、財報、政治事件（台北時間），每項寫「要看什麼」
9. **各國重點新聞**：美國、台灣、中國／香港、日本、南韓、歐洲、其他亞太、中東與地緣、拉美與其他、科技與產業、商品與加密。每則＝中文標題（連結到原文）＋來源與日期＋2–3 句中文重點＋「為什麼重要」。外文新聞一律翻成中文。每天總數目標 40 則以上，寧多勿漏，但不重複。
10. **風險雷達與翻轉條件**：目前追蹤的風險，各自的機率感受與影響
11. **資料限制與更正**：今天哪些資料沒查到、哪些只有單一來源、對前一日的更正
12. **來源清單**與免責聲明

寫作要求：

- 先結論後細節；每一節開頭一句話講完重點。
- 多用表格與條列，段落不超過 4 行。數字用 tabular 對齊，漲紅跌綠。
- 專有名詞第一次出現時簡單說明（讀者懂金融，但不必懂每個產業術語）。
- 不用誇張字眼；不堆砌形容詞。

## 五、版型與檔案

```
daily/
  index.html            首頁：最新報告摘要＋所有日期清單（讀 reports.js）
  reports.js            報告索引（window.REPORTS = [...]，最新的在最前面）
  assets/report.css     共用樣式（首頁與報告共用）
  assets/report.js      共用腳本（主題切換、目錄、上下篇）
  reports/YYYY-MM-DD.html
  state/view-log.md     觀點延續紀錄
  RULES.md              本檔
```

常用 class（詳見最近一份報告的實際用法）：

- 立場標籤：`<span class="stance s-bull|s-lbull|s-neutral|s-lbear|s-bear">`
- 漲跌：`<span class="up">`（紅）、`<span class="dn">`（綠）、`<span class="flat">`
- 區塊：`section.sec`、`.card`、`.kpis > .kpi`、`.callout`（加 `.warn` `.info`）
- 表格：外層 `<div class="tbl">` 讓它可橫向捲動；數字欄加 `class="num"`
- 情境表：`table.scn`
- 新聞：`.news-group > h3` 與 `article.news`（`.news-title a`、`.news-meta`、`.news-body`、`.news-why`）
- 清單打勾：`ul.checks > li.ok|li.no|li.half`

不需要後端。新增報告只需要：新增一個 html、在 reports.js 加一筆。

- 每天早上 08:00（台北時間）由 Claude 桌面版的排程任務執行；App 沒開時會在下次開啟時補跑。
