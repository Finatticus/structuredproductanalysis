# 市場日報｜早報：分析邏輯與報告標準

> 這份是**早報**的規則。盤後午報另見 `daily/RULES-PM.md`，週六週報另見 `daily/RULES-WK.md`。網站首頁、共用版面與 class 規格以本檔為準。

這份文件是每日早報的最高準則。每次產出或修改報告前，都要從頭到尾讀完，不能只憑印象。
規則要改時直接改這份檔案，並在 `daily/state/changelog.md` 加一行修訂紀錄。

- 網站：<https://finatticus.github.io/structuredproductanalysis/daily/>
- Repo：<https://github.com/Finatticus/structuredproductanalysis>。本機 `C:\Users\User\Desktop\news` 是它的 sparse checkout，只追蹤 `daily/`。不要動 repo 裡其他檔案。
- 讀者：在台灣、有金融背景的投資人，約 08:00 起閱讀。要的是「花 5 分鐘知道重點；有空時可以點進去看完整分析」。
- 語言：繁體中文、台灣用語。漲用紅、跌用綠。

## 一、最高原則

1. **時間界線：報告一律站在當天台北時間 07:00 的角度寫。**
   - 檔名日期 D 的報告，只能使用 D 日 07:00 以前已經公開的資訊。
   - 07:00 以後才發生或才公布的事（例如當天台股、日股、韓股的盤勢，當天 07:50 以後的數據），不寫進當天早報：台股與當天亞洲盤勢由當天 15:30 的盤後午報處理，其餘留給隔天早報。
   - 判斷方法：看來源的發布時間，換算成台北時間。不確定發布時間的，不用。
   - 早上 07:00 時各市場狀態：美股剛收盤（台北 05:00；美國夏令時間為 04:00）、歐股前一晚收盤、台日韓是前一交易日收盤。日本 07:50 公布的數據不能用，留給午報。
2. **即時性優先。** 所有數字都是當次重新查到的。不可沿用前一天報告的數字當成今天的，也不可用模型記憶裡的數字。模型的知識截止日遠早於現在，價格、利率、人事、政策一律以搜尋結果為準。差一兩天的資訊在這個市場可能已經過時。
3. **每個數字都有出處和時間。** 表格要標資料日期；新聞要附原文連結。
4. **查不到就說查不到，不可編造。** 數字、引述、連結都必須是實際看到的。連結必須是搜尋結果或抓取頁面上出現過的 URL。
5. **事實和判斷分開。** 機率一律標明是主觀估計。
6. **觀點要連續，改變要交代。** 每天和前一天比較：維持、上修或下修，並說明是哪個新資訊造成的。
7. **正反並陳，寫出翻轉條件。**
8. **早報、午報只在週一到週五出（週六另有週報，規則見 `daily/RULES-WK.md`）；新聞依窗口收錄。** 週二到週五：前一天台北 07:00 到當天 07:00（24 小時）。週一：上週五台北 07:00 到週一 07:00（涵蓋整個週末）。不和前一份報告重複。詳見 5.8。
9. **不確定的事寫在該段裡，不另開區塊。** 例如「台積電 ADR 溢價（待今晚美股開盤確認）」或「這個數字只有單一媒體來源」。報告不設「資料限制與更正」區塊。對前一天報告的更正，寫在相關段落，用一句「更正：昨天寫 X，正確是 Y」。
10. **不是投資建議。** 頁尾固定附免責聲明。
11. **三個核心目標（使用者 2026-11-21 訂，早報、午報、週報都適用）：** ①**資料要對、要精確**（最優先，不可為了速度犧牲）；②**從資料截止到上線不超過 45 分鐘**（早報 07:45、午報 16:15、週報 10:45；各報告的時間預算見流程）；③**不浪費 token**：只查報告會用到的，只讀需要的段落，子代理的字數與搜尋次數是上限不是目標，查核員只回報問題。三者衝突時依序取捨：時間不夠就照「時間不夠時的優先順序」把低優先段落寫短，絕不跳過查核。使用者不介入日常運作：規則的檢討與修改由週報的規則檢視自行評估（RULES-WK.md 第八節）。

## 二、市場範圍

- **主要市場（完整分析）：台灣、美國，兩者在早報中權重相同。** 篇幅、分析深度、觀點（短中長期、情境、翻轉條件）、總經頁都要對等；總覽與首頁也要同時呈現台美兩邊的觀點，不能只寫台股。每天都有完整的市場頁（盤勢、總經、短中長期觀點），總經頁也是台灣、美國分開各自詳細分析。
- **次要市場（簡要帶過）：日本、南韓、中國與香港、歐洲、印度與東南亞。** 放在「個別市場 → 其他」，每個市場一小段＋一張小表，只寫和台美有關的部分。日本、南韓另給一個短期立場標籤。不要在次要市場花太多篇幅。
- **全世界的重大事件不限國家都要寫。** 戰爭、政變、選舉、天災、重大政策、央行意外動作、大型企業事件等，只要可能影響市場，都要放進新聞，重大的要進專題，並在「總經 → 全球重點」寫傳導路徑。

## 三、每日作業流程

### 步驟 0：讀檔與前置檢查（必做）

1. 讀本檔全文，以及 **`daily/state/lessons.md`（查核教訓筆記）全文**：過去查核抓到的錯誤類型，寫作時主動避開。讀規則檔時，Read 工具如果顯示「PARTIAL view」或只讀到一部分，一定要用 offset 分段讀完，不能只讀前半。
2. **確認日期與時間：** 用系統時間確認今天日期、星期與現在時間。報告日期 D ＝ 觸發排程的那個平日（補跑規則見第九節）。**現在早於 06:20，代表是前一天漏跑的補跑：不產出，回報「早報略過（補跑時間不對）」。現在已晚於 14:00：不產出，回報「早報略過，當天交給午報」。**（排程 06:30 開始準備，時間界線仍是 07:00，見步驟 1「早報分兩段」。）確認 D 與前一個美國交易日是否休市（4.7「休市判斷」）。
3. **上鎖、收存殘檔、同步、防重複（依這個順序）：** 先在 `C:\Users\User\Desktop\news` 執行 `python daily/tools/runlock.py acquire am`：印出 BUSY 代表別的報告正在執行，停止並回報。上鎖後，之後不論發布成功或中途停止，最後都要執行 `python daily/tools/runlock.py release am`。接著執行 `python daily/tools/runlock.py stash am`：前一次中斷留下的未 commit 殘檔（含已 add 未 commit 的、規則檔與 `daily/tools/` 的改動、沒做完的 rebase）會存到 `_research/interrupted/`，再還原成最新 commit。印出 STASHED 時在回報寫一句「前一次中斷的殘檔已收存到 …」，照常產出（週報會在流程檢討裡記錄）；訊息裡有「還原後仍有殘檔」就停止並回報。然後 `git status`、`git pull --rebase --autostash origin main`。
   - 防重複只認已 commit 的：`git ls-files daily/reports/D.html` 有輸出、或 `reports.js` 已有 D 的早報：停止，回報「已產出」；停止前先看 `git status -sb`：有 ahead（已 commit 但上次 push 失敗），就先 `git pull --rebase` 再 push，並用 curl 確認網址 200，然後才回報「已產出（補推送）」。stash 的輸出不是 CLEAN 或 STASHED 開頭（例如指令出錯），也停止並回報。
4. 讀 `daily/state/view-log.md` 最上面一節：前一份的立場、機率、關鍵數字、翻轉條件、待追蹤事件、「明天要補查的」、「午報更新」、「之後已知的事件」。
5. **讀最近一份午報**（`reports/` 裡最新的 `*-pm.html`）。把它對台股觀點的更新、情境與翻轉條件當成今天的起點。觀點延續以 view-log 為主；報告 HTML 很大，只讀需要的段落（用 Grep 找到「觀點更新」「情境」「翻轉條件」的位置再讀那幾行），不要整份讀。如果它的日期早於最近一份早報（例如前一天午報沒出），改以最近一份早報＋view-log 為起點。
6. **最近一份早報**（`reports/` 裡最新、檔名不含 `-pm` 的 HTML）是今天的版型範本，沿用它的 HTML 結構和 class（第五節有完整規格）。複製後只在要改某一段時讀那一段。
7. **建立去重清單：** 用 `grep -o '<span class="n-t">[^<]*' 檔案` 把最近一份早報與最近一份午報的所有新聞標題列出來，交給新聞子代理（規則見 5.8）。**週一另外加上週六週報（`reports/*-wk.html`）的新聞卡片標題與「本週十大事件」標題**：週報已寫到週六 10:00，週一的「週末發生了什麼」只寫之後的新發展。

### 步驟 1：蒐集資料

**早報分兩段（06:30 開始準備，07:00 截止不變）：**

- **第一段（06:30–07:00，準備）：** 上鎖、同步、讀檔（步驟 0）；`python daily/tools/newreport.py am D` 建立報告骨架；跑 twdata.py（前一個台股交易日的資料早就公布了）與 `python daily/tools/usdata.py strength --cutoff "D 07:00" --out _research/D`（美股產業與個股強弱，只用已收盤日線，給美國子代理與理性市場資訊用）；開台灣、美國、全球、兩個新聞子代理（新聞先查到開跑當下）與專題補查子代理；主筆先寫台股數據、均線與關鍵價位、專題架構等不受 07:00 影響的部分。
- **第二段（07:00 以後）：** 先執行 `python daily/tools/waituntil.py 07:05`（用 Bash 工具，timeout 設 600000；已過 07:05 會馬上結束；還沒到就先寫其他段落，真的沒事做才等）。過了 07:05 才可以跑 `usdata.py quotes --cutoff "D 07:00"`（24 小時交易的商品、匯率、期貨要取 07:00 那一刻的價格；Yahoo 報價有幾分鐘延遲，所以等到 07:05；跑完確認這些列的「資料時間」是 07:00，不是就照實寫實際時間）。
- **最後新聞掃描：** 07:00 以後開一個子代理，筆記寫進 `news-c.md`，並直接交新聞卡片 HTML。指示要寫明：窗口是台北「新聞 A、B 開跑時間（主筆開子代理時就要記下 HH:MM）」到 D 07:00；去重清單＝步驟 0 的清單＋新聞 A、B 已收的標題；其他要求和新聞子代理相同（確認原文發布時間並換算台北時間、5.8 卡片格式、可信度、不可用記憶、只收 07:00 以前發布的）；約 10 次搜尋，也要看美股盤後與重大財報消息。主筆合併 A、B、C 三份新聞時再去重一次。
- **補跑或開始時已晚於 07:00：** 不分兩段。新聞 A、B 的窗口直接到 07:00，不開最後新聞掃描；usdata.py 開始時就可以跑。
- 07:00 以後才公布的資訊照舊不能寫進報告，只能放進 view-log 第 9 項。

**一開始就同時做兩件事：跑腳本＋開研究子代理（子代理不用等腳本，指示裡先寫好腳本輸出檔的路徑）。**

**腳本（約 3 分鐘，官方與行情數字一律以腳本輸出為準）：** 一律用 Bash 工具，在背景執行或把 timeout 設成 600000。同一時間只跑一支 twdata.py（證交所有頻率限制）。

```bash
cd /c/Users/User/Desktop/news
python daily/tools/twdata.py market prev-D --cutoff "D 07:00" --out _research/D   # 自動找前一個台股交易日：加權、均線、成交值、漲跌家數、類股、成交金額前 20 名、三大法人（含連續天數與月累計）、融資、外資前 10 名、櫃買、台指期（含夜盤）、期貨未平倉、P/C
python daily/tools/usdata.py quotes --cutoff "D 07:00" --out _research/D             # 07:05 以後才可以跑。美股指數與 AI 股、台積電 ADR、美債（參考）、匯率、商品、比特幣（截止時價格）、歐股、亞股、日韓重點個股
```

- twdata.py 最後有「總結」；usdata.py 要看每一列的備註有沒有「查無」「抓取失敗」「腳本錯誤」。**早報用的是前一個交易日的資料，照理全部都已公布；任何「尚未公布」「查無」「抓取失敗」「腳本錯誤」都是異常，要先手動到官方網站確認，不可照寫。** 腳本提示「可能是休市日」時照 4.7「休市判斷」處理。
- 腳本抓到的數字直接用，不要再手動抓，也不要再請子代理抓。夜盤：早報用標為 D 的盤後列（腳本輸出有說明）。成交量的倍數一律用 twdata 的「比較用均量（不含當天）」那一行；法人一週合計用「本週累計」那一行（原始值加總），不要自己把四捨五入後的日數字相加；週一早報的資料日是上週五，那一行就是「上週」合計。
- 匯率、商品、比特幣、美股期貨是「截止時價格」，日漲跌是和 24 小時前比，報告要照這個寫法標示。美債殖利率用腳本輸出的 CNBC 日線收盤（4.7「口徑固定」）；新台幣收盤用台北外匯經紀 16:00 收盤，腳本的 TWD=X 只當參考。

**研究子代理（5–6 個，在背景平行）：** 結果寫成 Markdown，固定放在 `C:\Users\User\Desktop\news\_research\YYYY-MM-DD\`（本機留存，不進 git），檔名固定 `tw.md`、`us.md`、`global.md`、`news-a.md`（台灣、美國新聞）、`news-b.md`（全球、日韓、中國新聞），以及 `themes.md`（專題補查）。**腳本已經抓的數字不要再抓**；每個子代理照下面分工表的「必查清單」做，清單做完才算完成。每個子代理的指示都要包含：

- 今天日期與 **07:00 時間界線**，以及「所有內容來自搜尋結果，不可用記憶」。
- 每個數字和事實附來源 URL、發布時間；區分「已確認（官方或兩個獨立來源）」與「單一來源」；查不到寫「查無」。
- 腳本輸出檔的路徑（`_research/D/official-tw-YYYYMMDD.md`、`official-us-YYYYMMDD.md`），告訴它這些不用再抓。official-us 要到 07:00 以後才會產生：**子代理不可以自己跑 usdata.py，也不要自己抓行情數字**，價格一律等主筆的腳本輸出。
- **筆記要精簡：** 以表格為主，每列附來源與日期，不寫長篇敘述。台灣、美國、全球三個子代理各約 15,000 字元（含表格與網址）、30 次搜尋；兩個新聞子代理各約 15,000 字元、25 次搜尋（週一涵蓋週末，各放寬到 20,000 字元、35 次）；專題補查每題約 3,000 字元、8 次搜尋。打開網頁確認原文與發布時間不算在搜尋次數裡，但每則新聞只開原文一次。先讀 `daily/state/lessons.md` 裡和研究有關的教訓。
- 新聞每則要有：中文標題、原文標題、3–5 條中文重點（含數字、人名、日期）、2–4 句分析（對台美市場的影響、時間尺度、後續觀察）、URL、發布時間（原文時區與台北時間）、可信度。格式對應 5.8。

**兩個查核員平行進行（比較快）：**

- **數字查核員：** 核對所有數字。**第一步先跑 `python daily/tools/crosscheck.py 報告.html _research/{D}/official-*.md`**，它會在幾秒內列出「和官方數字很接近但不一樣」的地方（疑似抄錯），優先處理；這只是篩選，列出來的不一定錯，沒列出的也不代表都對。接著重跑腳本（輸出到 `_research\{D}\verify\`），和報告逐項比對；**和主筆的數字不同時，先比對主筆的 `raw-tools\` 原始檔（台股）或 official-us 檔頭的抓取時間（美股）：差異來自官方在截止後修正的（例如成交金額、三大法人修正版），不算錯誤，報告以截止時的版本為準。** 重跑同一支腳本抓不出腳本自己的錯，所以還要挑 5 個以上的關鍵數字用另一個獨立來源（官方網頁、中央社、鉅亨網、通訊社）核對，而且每天至少包含一項容易解析錯的：融資金額單位（仟元）、類股漲跌正負號、台指期夜盤用哪一列、櫃買指數與成交金額單位、P/C 比。腳本沒有的數字（總經、財報、目標價）照常回到原始來源核對。

查核項目：

1. 逐一核對報告裡的每個數字：指數、漲跌幅、法人買賣超、利率、匯率、商品、總經數據、央行利率與會議日期、財報預期。每個至少回到一個來源確認；關鍵數字（主要指數收盤、法人買賣超、政策利率）要兩個來源或官方。
2. 檢查時間界線：任何 07:00 以後才公布的資訊都要刪掉。**行前稿與預告：**「抵達、出席、會面、會談、發表、公布、生效、簽署、通過」這類動詞，逐一確認在截止前已經發生；只有預告的，改寫成「預計」「將」並寫預定時間。
3. 檢查即時性：每個數字是不是最新的。例如報告用了兩天前的殖利率，但其實昨晚已有新的收盤，要換掉。
4. 驗算：漲跌點 ÷ 前收 = 漲跌幅；距離百分比；情境機率加總 100%；日期與星期是否對得上。
5. 檢查每一則新聞：發布時間是否在新聞窗口內、是否和去重清單重複（5.8）、連結是否有效。**逐句核對：**卡片的一句話重點、每一條「重點」、分析裡的事實數字，都要能在卡片列出的原文找到對應句；找不到的，要嘛補上那篇來源的連結，要嘛刪掉。專題時間線、十大事件、理性市場資訊的「原因」欄這類「事件＋來源」的段落也照這個方式核對；理性市場資訊頁另外確認沒有操作指令或推薦語氣（5.10 列的用語），產業與個股的近 5、20 日數字都取自腳本輸出。
6. 檢查專題的視覺（時間線、長條圖等）上的數字和日期是否和內文一致、是否正確。
7. 檢查和前一份午報、前一份早報的一致性：數字有沒有矛盾、觀點變化有沒有交代原因、比較基準是否正確（4.3）。
8. 檢查 `reports.js` 第一筆（points、headline、stats、views）與 view-log 最上面一節（立場、機率、關鍵數字）是否和報告內文一致。
9. 檢查範本殘留：日期、時間、`.asof`、新聞窗口文字、頁尾、`<title>` 是否都是今天的（5.9）。

主筆另外自行確認：用語都是「AI」不是「我」；每張表都有 `thead`；`<head>` 有圖示與 manifest；手機寬度檢查（方法見 5.9）。

主筆依清單修正（報告、reports.js、view-log 都要改）：查核員回報的每一項，主筆先用原始來源確認真的錯了才改。修正的內容不需要在報告裡另外交代，除非是更正前一天的報告。

**修正後複核（1 輪）：** 開一個新的獨立子代理，只檢查改過的地方（同一個數字在摘要、表格、圖表、reports.js、view-log 出現的每一處），7 分鐘內交回。複核仍有必改項目：主筆只能改成複核員給的、有來源的值，或刪除、改寫成不含該數字的句子（找不到可靠來源就寫「查無」），用 grep 確認每一處都改了，然後發布，不再開第 2 輪（不會帶著未經查核的新數字發布）。發布前主筆再跑一次 `python daily/tools/residue.py 新報告 範本報告`，確認沒有範本殘留，並用 `grep -c '【待' 新報告` 確認是 0（newreport.py、snapshot.py 留下的待填、待確認全部處理完）。檢查全部通過才發布，不可先發布再檢查。

**記錄教訓（每次都要做）：** 查核發現的每一類問題，都寫進 `daily/state/lessons.md`。寫法照該檔開頭的說明：規則＋這次的例子；同類型已有就補例子。這次沒有發現問題，就不用改。**早報、午報排程執行時不可修改規則檔（`RULES*.md`）和腳本（`daily/tools/`）。** 發現腳本有錯，這次報告改用手動抓取的正確值，並把問題寫進 `lessons.md` 最下面的「待週報處理」一節，回報裡也要寫出來；同類錯誤達 2 次，也只在那一節寫「建議升級：…」，由週報的規則檢視評估後決定是否修改（RULES-WK.md 第八節）。唯一例外：腳本執行時直接出錯（例外、語法錯誤），而且最近一次改它的是週報規則檢視的 commit，可以用 `git checkout 那個commit~1 -- daily/tools/該檔` 還原成前一版、和報告一起 commit（只限還原，不可改寫），並寫進「待週報處理」。

## 四、分析框架

### 4.1 時間尺度

| 尺度 | 期間 | 主要驅動 | 主要依據 |
| --- | --- | --- | --- |
| 短期 | 1–2 週 | 事件、籌碼、情緒、技術面 | 行事曆上的催化劑、期貨選擇權部位、融資、均線與缺口、波動率 |
| 中期 | 1–3 個月 | 央行路徑、獲利修正、資金流向、估值 | 利率期貨定價、獲利預估修正、外資動向、信用利差 |
| 長期 | 6–18 個月 | 景氣循環、產業趨勢、獲利成長、估值水位、結構性風險 | GDP 與獲利預估、資本支出週期、融資條件、政策與地緣 |

### 4.2 每個尺度都要檢查的六個面向

1. **政策與利率**：央行在升、降還是觀望？市場定價和央行說法有沒有落差？
2. **總經與獲利**：數據在加速還是減速？企業獲利預估上修還是下修？
3. **估值**：本益比相對歷史和相對利率在哪裡？已經反映多少？
4. **資金與籌碼**：誰在買、誰在賣？槓桿高不高？
5. **情緒與技術**：恐慌還是貪婪？關鍵價位在哪？
6. **事件與地緣**：行事曆上有什麼？尾部風險是什麼？

### 4.3 立場、信心與機率

- 五級立場：**偏多／中性偏多／中性／中性偏空／偏空**。
- 信心：高／中／低。
- 與前一日比較：維持、上修、下修，附一句原因。第一份報告寫「首份」。
- **比較基準：** 台股短期和「最新的立場」比：最近一份午報有更新就和午報比，否則和前一份早報比，並在括號註明比較對象，例如「維持（對照 11/16 午報）」。台股中長期與美國各期，一律和前一份早報比。**週一早報：週六週報有更新的立場，改對照週報**（例如「維持（對照 11/21 週報）」），週報的情境與翻轉條件也是週一的起點。
- 情境表至少三種（樂觀／基本／悲觀），每種有觸發條件、可能區間、主觀機率，加總 100%。
- 翻轉條件：「看到什麼 AI 會改變看法」，要寫具體價位或數據。
  - **價格條件單獨就能觸發**：收盤跌破（或站上）關鍵價位，就照條件調整立場或信心，不可以再加「且」籌碼條件才算數。籌碼、利差只能用來「加速」或「確認」（例如「或外資淨空站上 10 萬口」），不能用來擋住價格條件。
  - **籌碼條件要對應當下真正的賣壓（或買盤）來源**：去槓桿行情看融資單日增減與自營商避險，ETF 賣壓看外資 ETF 買賣超，外資轉向才看外資現貨與期貨。每份報告寫條件前，先看腳本的法人、融資、期貨數字，確認條件裡的籌碼指標還是當下的主角；不是就換掉並寫明原因。
  - 例：2026-11-16 到 11/19 的台股下修條件連 7 份報告要求「價格破位且外資台指期淨空 ≥10 萬口」，價格 11/16 就破，賣壓卻來自融資與自營避險，外資淨空反而減少，下修晚了 4 個交易日（11/21 週報成績單）。
- 機率是主觀估計。前後兩天的機率變動要有理由；沒有新資訊就不要為了變而變。

### 4.4 利空利多的分類

遇到重大事件先分類，再判斷消退速度：

- **事件面**（人事、單一公司、單一數據）：通常幾天到幾週消化。
- **政策面**（監管、關稅、選舉）：漸進、持續數月。
- **資金面**（利率、流動性、信用、去槓桿）：最慢，最影響估值。
- **基本面**（需求、獲利、景氣）：決定長期方向。

多層疊加時要分開寫。

### 4.6 常見錯誤

查核實際抓到的錯誤類型與例子，記在 `daily/state/lessons.md`（每份報告開始前必讀）。以下是分析上的常見錯誤：

- 把國安基金進場日當最低點
- 把單日反彈當趨勢反轉（要看外資是否連續回補）
- 直接套用歷史前例而不比較利率環境與事件性質
- 只引用看多或只引用看空的機構
- 把二手整理站的數字當原始資料
- 把「市場預期」寫成「已經發生」
- 忽略時區：美股「週二盤後」是台北週三清晨；日本數據 07:50 公布
- **用到 07:00 以後的資訊**

### 4.7 分析方法細則（怎麼算、怎麼判斷）

**估值**

- 本益比要註明口徑：歷史（過去四季獲利，金管會、證交所公布的多為此口徑）或預估（未來 12 個月，市場評論多為此口徑）。兩者不能混用、不能直接比較。
- 股票風險溢酬（簡算）＝ 1 ÷ 預估本益比 − 10 年期公債殖利率。接近 0 或為負，代表股票相對債券沒有吸引力，本益比難以擴張，指數只能靠獲利成長上漲。
- 估值高低要同時和三個基準比：自身歷史平均、利率水準、同業或其他市場。
- 台股另看股價淨值比與現金殖利率；權值股占比高（台積電逾四成），要拆開看「台積電」與「其他」。

**技術面（台股）**

- 均線一律用證交所 FMTQIK 的每日收盤自己算（5、10、20、60、120、240 日），不用媒體數字。
- 指數相對位置 ＝ 收盤 ÷ 均線 − 1；距關鍵價位 ＝ 價位 ÷ 收盤 − 1。
- 缺口：向上缺口是今日低點 ＞ 前一日高點；向下缺口是今日高點 ＜ 前一日低點。回補是之後的價格碰到缺口另一端。
- 回吐比例 ＝（反彈高點 − 現價）÷（反彈高點 − 起漲低點），註明用收盤或盤中高低點。
- 量價：大跌爆量（恐慌換手）和大跌量縮（跌停鎖死、賣壓未釋放）意義不同，要分開判斷。
- 均線排列：月線（20）與季線（60）交叉、季線與年線的方向，用來判斷中期趨勢。

**籌碼（台股）**

- 外資現貨：看當日、連續天數、當月累計；扣除 ETF（尤其主動式 ETF）的套利與短線部位，才是對個股的真實方向。
- 外資台指期淨未平倉：看方向與變化量。大跌時外資空單沒有增加，是「沒有加空」的訊號；空單創高並持續增加，才是轉空的訊號。投信的期貨多單多半是 ETF 避險，不能把外資空單全部當成看空。
- 結算週：看近月與次月未平倉分布（轉倉進度）、逆價差（用最後成交價與結算價各算一次）。
- 自營商分「自行買賣」與「避險」：避險部位是權證與 ETF 造市的被動調整，跌愈多賣愈多，會放大波動。
- 融資：餘額變化、整戶維持率（金管會口徑與媒體口徑不同）。融資在反彈中增加＝散戶追價，之後下跌會變賣壓。
- 判斷「去槓桿」或「轉空」：同時看外資期貨、成交量、跌幅結構（集中或全面）、投信動向、匯率。三項以上偏同一方向才下結論。這一段是用來判讀賣壓來源與市場性質，**不是翻轉條件的門檻**；翻轉條件照 4.3（價格單獨就能觸發）。

**利率、匯率與資金傳導**

- 美債 10 年殖利率上升 → 壓低全球股票估值，高本益比股受影響最大。
- 美台利差擴大、美元走強 → 新台幣偏弱 → 外資匯出壓力；央行進場與出口商拋匯是支撐。
- 日圓急升 → 日圓套利交易平倉 → 全球風險資產波動。
- 油價 → 整體通膨（2–3 個月）→ 核心通膨（再落後 3–6 個月）→ 央行路徑。

**情境與機率**

- 基本情境通常 40–50%，樂觀與悲觀各 20–35%，加總 100%。遇到下面的「情境重設」或「主情境的限制」時，不受這個範圍限制（例如悲觀情境可以是最高機率）。
- 機率的變動要對應到具體的新資訊；沒有新資訊不變。單日變動超過 15 個百分點，必須是重大事件，並寫明原因。
- **情境重設：** 收盤已經跌破（或突破）情境表的區間（三個情境合起來的整個範圍）、或悲觀（樂觀）情境已經實現時，不從舊數字小調，要以最新收盤**重新設定三個情境的區間與機率**，並寫明「區間重設（原因）」；這種情況不受上一條 15 個百分點的限制。
- **主情境的限制：** 止穩訊號（台股 `tw-signal`）成立少於 2 項時，最高機率的情境不可以是「區間震盪／打底」；上漲時改用過熱訊號清單，過熱訊號成立 2 項以上時，最高機率的情境不可以是「續漲」。
- 例：2026-11-16 早報到 11/19 午報 8 份報告，台股最高機率都是「震盪／打底」，悲觀機率每次只調 0–6 點，悲觀情境每次都在 4 個交易日內實現（11/21 週報成績單）。
- **線索與確認指標：** 美股盤後價、期貨盤中價只當線索，不可以單獨拿來下調悲觀機率或撤銷已觸發的翻轉條件；信用利差通常落後股價，只當確認，不可當成「不下修」的理由。判斷要不要下修，同時看同步指標：VIX、漲跌家數（市場寬度）。例：11/18 早報因輝達盤後上漲調降跌破年線機率，兩天後就跌破；11/17 早報用「利差仍窄」當不下修的理由（11/21 週報成績單）。
- 立場要和情境機率一致：例如悲觀情境機率高於樂觀，立場不應是偏多。
- 翻轉條件要事先寫好，下一份報告先檢查條件是否觸發，再決定是否改立場（不能事後找理由）。

**專題的選擇**

- 優先順序：會在 1–2 週內影響台美市場方向的事件 ＞ 會改變中期判斷的政策或數據 ＞ 長期結構議題。
- 同一題目連續出現時，只寫新的發展與判斷的變化，不重抄背景。

**新聞的選擇**

- 必收：會影響台美市場的政策、央行、重要數據、權值股與大型企業事件、地緣衝突、全球重大事件（不限國家）。
- 不收：重複的稿件、沒有新資訊的評論、時間窗外的稿件。
- 同一事件有多篇報導時，選最原始、最權威的一篇，其餘只用來核對。

**來源與可信度**

- 分三級：官方與交易所 ＞ 通訊社與主流財經媒體 ＞ 二手整理、部落格、Substack。第三級只能當線索，引用時標「非官方來源」。
- 只有一個來源的數字標「單一來源」；兩個來源不一致時，兩個都寫，並說明採用哪一個與原因。
- 證交所等官方資料可能在當天稍晚修正（例如三大法人初版與確定版），引用時以報告時間界線當下公布的版本為準，並註明。

**口徑固定（每天一樣，才能前後比較）**

- 外資台指期淨未平倉：只算「臺股期貨」（TX）的口數，不含小型台指、微型台指。要提小台時另外列。
- 成交值：證交所 FMTQIK 或 MI_INDEX 的「總計」成交金額（含 ETF 等），單位億元。
- 新台幣：台北外匯經紀公司 16:00 收盤價（中央社、鉅亨網報導的收盤價即此口徑）。usdata.py 的 TWD=X 是國際報價，只當參考。
- 美債殖利率：一律用 **CNBC 日線收盤**（美東約 15:00 的債市收盤，2 年、10 年、30 年同一來源，利差才一致；和 CBOE 指數同口徑）。CNBC 報價頁在美東 17:05 前後的「最後成交」和日線收盤不同，不要混用，日、週變動也一律用日線收盤相減。usdata.py 已直接輸出 CNBC 日線收盤（只列截止時已收盤的那一天），CNBC 抓取失敗時才會退回 CBOE 指數並標明。
- 行情資料過期：usdata.py 會在 Yahoo 日線比「截止時應該已收盤的交易日」舊時，改用 CNBC 報價並在備註寫明；兩邊都沒有新資料時備註標「**可能過期**」（該市場休市時也會被標，要確認）。看到「可能過期」就不能直接寫進報告。
- 匯率（新台幣除外）、商品、比特幣、美股期貨：早報用 usdata.py 的「截止時價格」，日漲跌是和 24 小時前比，報告標明「截至 07:00」。
- 距歷史高點、52 週高低：用盤中最高、最低（加權指數看 twdata.py 第 1b 節，來源 MI_5MINS_HIST，涵蓋近 13 個月，更早的歷史高點要另外確認；個股看 stockviz.py stats）；收盤口徑只當參考，兩種都寫時要標明。
- 週變動：和 5 個交易日前的收盤比。
- 台積電 ADR 溢價＝TSM 收盤 × 前一交易日新台幣 16:00 收盤 ÷ 5 ÷ 台積電收盤 − 1（主筆用腳本數字自算，註明匯率日期）。
- 外資個股買賣超（TWT38U、T86）：用「外資及陸資（不含外資自營商）」那一欄，和三大法人表一致（twdata.py 已照這個口徑）；外資自營商不為 0 時另外註明。
- 指數漲跌來源：台積電與權值股的貢獻點數用 twdata.py 第 11 節（AI 估算）。
- 商品與匯率切換：11/17 早報以前用的是前一日結算價或收盤，改用截止時價格的第一天（11/18 早報）要在快照表下註明，和前一天比較時用 view-log 記的 11/17 07:00 腳本值；期貨換月前後，日變動改用同一合約並註明。
- 成交金額：午報時抓到的當天數字是 15:30 前的版本，晚間可能因盤後交易併入而變大；隔天早報用最終值，和午報不同時註明。
- 均線：每日收盤價的簡單平均（不是加權或指數平均）；資料不足 N 日時不算。
- 三大法人：證交所 BFI82U，單位億元（官方為元，除以 1 億，取到小數兩位）。外資用表上「外資及陸資（不含外資自營商）」這一列（和媒體報導的口徑相同）；「外資自營商」通常為 0，不為 0 時另外註明。自營商分「自行買賣」與「避險」兩列；三大法人合計用表上「合計」列。和媒體數字不一致時，以官方為準並註明。

## 五、報告版面標準（每份都一樣）

### 5.1 原則

- **分頁，不要一頁拉到底。** 頂部一排主分頁；「個別市場」裡再分市場，市場裡再分子分頁。一次只顯示一個區塊。
- **每個區塊最上方都有摘要，而且摘要要夠詳細。** 讀者只看摘要就要能知道：結論是什麼、為什麼（附關鍵數字）、和前一天比有什麼變化、最大的風險、接下來要看什麼。見 6.1 的長度標準。
- 投行研究報告風格：淺色、白底、深藍主色、細線表格、方角、無表情符號、無漸層。
- **摘要分三層，外觀要看得出輕重**（CSS 已自動處理，只要放對位置）：
  - 第一層：分頁最上方的總摘要（`section.panel > .summary`）。淺藍底、深藍粗上框，標題字最大。標題用「摘要」或「專題總摘要」。
  - 第二層：子分頁的摘要（`.subpanel > .summary`）。淡青綠底、青綠左粗線。標題用「本頁摘要」「專題摘要」「結論」。
  - 第三層：子分頁內再分的子分頁摘要（`.subpanel .subpanel > .summary`）。淡米色底、金色左細線，最輕。
  - 每層摘要都要有底色，不能和內文一樣是白底；摘要標題（`.summary-h`）字要夠大，後面接一條細線。
- **小標題與配色**（CSS 已處理，寫 HTML 時用對元素即可）：
  - `h3` 小標題和上一段之間要有明顯間距，左側有金色細條；不要把 `h3` 緊接在上一段文字後面而不分段。
  - 專題敘述的段落標題用 `div.essay` 裡的 `h4`（青綠色、下方細線）。
  - 配色只用四種：深藍（主結構）、青綠（摘要第二層、提示框、AI 看法）、金色（小標題、第三層摘要）、紅綠（漲跌）。琥珀色只用在警示（`.callout.warn`）。例外：午報的識別色赭色（CSS 變數 `--pm`）只用在首頁的午報卡片與午報清單。不要再加其他顏色。
- 先結論後細節；多用表格與條列；段落不超過 4 行。

`markets` 分頁最上方先放跨市場摘要（台灣、美國各 2–3 句，加上相對強弱與其他市場一句），再放市場選單：

1. 摘要框：三個立場標籤（短中長期）＋ 5–7 條重點，每條 1–3 句。
2. 數據列（`.kpis`）：6–9 個關鍵數字。**台灣數據列固定要有上市、上櫃融資兩格（前一交易日，twdata.py 第 5 節）**，增減為主、餘額為輔：

   - `總經`：該國總經數據表與央行重點（詳細分析放在總經頁，這裡寫和股市最相關的部分）
   - `短期`、`中期`、`長期`：5.4 的觀點格式
   - 台灣另加 `tw-signal` 止穩訊號（或依情況改為過熱訊號）

### 5.4 觀點頁格式（短期、中期、長期）

1. 標題列：期間、立場標籤、信心、與前一日比較
2. 摘要框：一句結論＋ 3–5 句說明（原因、關鍵數字、最大風險、和昨天比的變化）
3. 正反理由（兩欄）
4. 情境表（條件、可能區間、主觀機率）＋機率條
5. 翻轉條件（`.callout`），寫具體價位或數據
6. 尚待釐清的事直接寫在相關段落，標「待確認」

### 5.5 專題

- 選當下最重要、最即時的 2–4 個事件，不限國家（只要可能影響台美市場）。不要選已經被市場消化完的舊題目。
- **專題是深入分析，不是數據表。** 每個專題要有 4–6 段、每段 2–5 句的敘述，把事情的來龍去脈、因果關係和AI 判斷講清楚；數據表是佐證，放在敘述後面。
- 專題分頁最上方：專題總摘要（每個專題 2–3 句，第一層）。
- **每個專題都要有視覺輔助，敘述保留不刪。** 文字負責講道理，視覺負責讓讀者不用自己拼湊。每個專題至少 2 個，依題目選適合的，不要硬塞：
  - **時間線**（`ol.timeline`）：事件有前因後果、有後續日程時用。已發生的事、重大節點（`li.key`）、利空（`li.bad`）、未來日程（`li.next`）用不同圓點區分。
  - **因果流程**（`div.flow`）：解釋傳導機制時用，例如「油價 → 通膨 → 升息 → 估值」，可加 `div.flow-back` 寫反向或解方。
  - **比較卡**（`div.cards3` 或 `div.cards2` 裡放 `div.ccard`）：有幾條路線、幾種方案、雙方籌碼時用。
  - **長條圖**（`div.bars`）：比較大小、前後變化、分項組成。正負都有時用 `div.bars.center`（中線為 0）。寬度是相對比例，要在 `p.viz-note` 寫單位、來源或「AI 主觀評估」。
  - **證據天平**（也是 `div.bars`）：判斷兩種解讀哪個較可能時用（例如「去槓桿 vs 轉空」）。每列一種解讀，`.bl` 寫「支持 A」「支持 B」「待確認」，`.bv` 寫項數或關鍵證據，顏色用 `.bf.teal`（支持 A）、`.bf.dn`（支持 B）、`.bf.gray`（待確認），寬度＝該列項數 ÷ 總項數。下方用 `p.viz-note` 列出每一項證據。
  - **對照表**：情境、關鍵數字、影響表維持用表格。
  - **股價走勢圖、目標價區間圖**（`svg.cv`，主要給午報個股專題用，早報需要時也可以用）：一律用 `daily/tools/stockviz.py` 由資料產生，不要手寫座標。股價資料存成 CSV（欄位 `date,open,high,low,close,volume`）。
    - `python daily/tools/stockviz.py stats CSV`：印出最後收盤、5–240 日均線（簡單平均）與相對位置、52 週高低、1／3／6 個月與今年以來報酬、均量、RSI。報告裡的均線與報酬以這裡的結果為準。
    - `python daily/tools/stockviz.py price CSV --days 120 --ma 20,60,120 --title "標題"`：輸出走勢圖（收盤線＋三條均線＋成交量）的完整 `div.viz`。
    - `python daily/tools/stockviz.py target --cur 現價 --pts "券商A=價,券商B=價" [--avg 共識 --src "資料商 日期"] --unit 元 --title "標題"`：輸出目標價區間圖（各家目標價、平均、現價）。
    - `python daily/tools/stockviz.py bars --items "標籤=數值,…" [--signed] [--unit 億元] [--fmt ,.1f] [--color teal]`：輸出 `div.bars`，寬度依最大值自動計算；`--signed` 輸出正負長條（`div.bars.center`）。用在營收、EPS、營收結構、法人買賣超等。
    - `python daily/tools/stockviz.py trend --labels "Q1'25,…" --bars "數值,…" --bar-name 營收 [--bar-scale 1000 --bar-fmt .1f] [--line "數值,…" --line-name 毛利率 --line-unit %] [--line2 …] [--est "Q4'26F"] --title "標題" --note "說明"`：輸出時間序列圖（直條在下、折線在上，每個點直接標數字；`--est` 標示的點畫成虛線框，代表預估或財測）。**時間序列（營收、利益率、EPS、月營收等）一律用這個，不用橫條圖**；橫條只用在比較不同項目。
    - 工具輸出的 HTML 直接貼進報告；要改數字就改資料重跑，不要手改。
- 所有視覺都包在 `div.viz`（標題 `div.viz-h`），兩個並排用 `div.viz-grid`。圖上的數字要和內文、表格一致，也要經過查核。
- 視覺的 HTML 寫法從最近一份有該種視覺的報告複製（或用上面的工具產生），不要自己發明新 class。
- 每個專題一個子分頁，id 為 `th-英文短名`（例如 `th-nvda`、`th-rates`），固定結構：
  1. 專題摘要（第二層）：一句粗體結論＋ 3–5 句說明
  1.5 視覺輔助：最重要的一張（通常是時間線或因果流程）放在摘要後、敘述前；其他放在敘述後、「市場 vs AI」前
  2. 深入分析（`div.essay`，用 `h4` 分段，常見段落）：為什麼這件事重要／背景與脈絡；拆解關鍵機制（例如數字背後的意義、利潤往哪裡移動、誰受惠誰受害）；不同的可能路徑與各自的代價；尚未被市場注意的風險；對台灣、美國的傳導路徑
  3. 市場怎麼看 vs AI 怎麼看（`div.view-box`，`.mkt` 與 `.mine` 兩格）
  4. 關鍵數字或時間線表
  5. 情境與主觀機率
  6. 觀察清單（`.callout`）：具體指標與日期

### 5.6 總經與跨資產

這一頁的分析要比市場頁更細，不能只列數字。**台灣與美國分開，各自詳細分析。** 子分頁固定順序與 id：

| id | 名稱 | 內容 |

### 5.7 行事曆

- 欄位：時間（台北）、市場、事件、**分析**。「市場」欄不換行（`td.nw`）。
- 每列加 `data-mkt`：`tw`、`us` 或 `other`；跨市場的事件可以寫多個，用空白隔開（例如 `data-mkt="us other"`）。分組列 `tr.grp` 不加。
- 頂部放篩選列：`<div class="fbar"><button data-filter="all">全部</button><button data-filter="tw">台灣</button><button data-filter="us">美國</button><button data-filter="other">其他</button></div>`。
- 「分析」要寫 AI 的看法：預期值與前值、市場目前怎麼定價、結果偏多或偏空時各會怎樣、AI 特別關注的細項。不要只寫「看是否升息」這種一句話。
- 重要事件（會改變觀點的）用 `tr.hl` 標示。

### 5.8 新聞

- **時間窗：** 週二到週五只收前一天台北 07:00 到當天 07:00（過去 24 小時）發布的新聞；週一收上週五台北 07:00 到週一 07:00（涵蓋週末）。窗外的新聞不放進新聞頁，需要的話可以在分析段落裡當背景提到。週一的新聞數量可以比平日多。
- **去重清單：** 最近一份早報與最近一份午報的所有新聞標題（步驟 0 第 7 項）。
- **不和前一份早報重複：** 前一份早報已收的事件不再列，除非有新的發展（那就只寫新的發展）。
- **和午報的關係：** 早報窗口 24 小時，會和前一天午報（07:00–15:30）重疊。午報已收的事件可以再收，但必須寫出之後的新發展，或從全球角度重新歸納；沒有新東西就不收。台股盤後細節不必重抄，直接引用午報的結論。
- **只要重點，但不能漏掉重要事件。** 不設最低數量，一般約 12–25 則。研究時要逐一掃過台灣、美國、日本、南韓、中國、歐洲、中東、俄烏、其他地區的重大事件（不限國家）、AI 與半導體、能源、央行，確認沒有漏掉。台灣、美國的新聞最多；日本、南韓只收重要的。
- 每則用可展開的卡片（`details.news`）：
  - 收合時看到：市場標籤、中文標題、來源與台北時間、一句話重點
  - 展開後看到：**重點**（3–5 條中文條列，含數字、人名、日期）、**分析**（2–4 句，對台美日韓的影響、時間尺度、後續要觀察什麼）、**原文連結**
- 頂部篩選列一律用 `div.fbar`（與行事曆共用同一套程式），按鈕固定為 `all` 全部、`tw` 台灣、`us` 美國、`gl` 全球、`jp` 日本、`kr` 南韓。每則新聞的 `data-mkt` 用這些值：日本、南韓以外的國家與跨國事件一律用 `gl`；一則新聞同時屬於兩個市場時可以寫兩個值，用空白隔開（例如 `data-mkt="us gl"`）。標籤 `span.n-mk` 寫主要的那一個市場。
- 外文新聞一律譯成中文整理，不要只放連結。

### 5.9 HTML 與 class 規格

檔案：`daily/reports/YYYY-MM-DD.html`，`<body data-report="YYYY-MM-DD">`。共用 `../assets/report.css`、`../assets/report.js`、`../reports.js`。最可靠的範本是最近一份早報。

- **`<title>`：** 「市場日報 早報 YYYY-MM-DD」；`<meta name="description">` 一句話寫當天重點。
- **刊頭：** kicker「市場日報 · 早報 · YYYY-MM-DD Mon」；`h1` 一句話標題；meta 寫「資料截至台北時間 MM/DD（X）07:00」與各市場資料日期（例如「美股：MM/DD 收盤」「台股：MM/DD 收盤」；休市寫「美股：MM/DD 休市」）。右上按鈕：「← 前一份早報」「首頁」「後一份早報 →」（`#prevBtn`、`#nextBtn`，由 report.js 自動連結）。
- **星期寫法：** kicker 用英文縮寫（Mon、Tue、Wed、Thu、Fri）；內文、meta、`reports.js` 的 `weekday` 用中文（一、二、三、四、五）。
- **頁尾：** `p.foot` 免責聲明，文字固定：「本報告由 Claude 依公開資訊整理分析，資料截至台北時間 YYYY-MM-DD 07:00。立場與機率為主觀判斷，不構成投資建議。」
- **分頁標題列：** 每個 `section.panel` 第一行是 `<div class="ph"><h2>名稱</h2><span class="asof">資料時間或範圍</span></div>`。
- **範本清理：** 複製最近一份早報後，先全文搜尋並換掉這些範本殘留，再開始寫：舊日期（`YYYY-MM-DD`、`MM/DD`、星期）、`<title>`、`description`、`data-report`、kicker、刊頭 meta、每個 `.asof`、新聞窗口文字、頁尾日期。11/16 早報是特例（以 08:00 為界），用它當範本時要把所有「08:00」改成「07:00」。查核第 9 項會再檢查一次。
- **手機寬度檢查方法：** 執行 `python daily/tools/mobilecheck.py daily/reports/新報告.html`。它用無頭 Chrome 在 375×812 開報告、所有分頁同時打開，確認頁面不會左右捲動；第一行是 OK 才算通過，FAIL 會列出造成超寬的元素，要修到 OK。**不要用預覽伺服器（`daily-site`）或瀏覽器面板做這項檢查**：那些要人按允許，排程時會卡住。印出 ERROR（瀏覽器開不起來）時，在回報裡寫「手機寬度未檢查」，不要因此停住。

- **`<head>` 必須包含 APP 圖示與 manifest**（從最近一份報告整段複製）：`favicon-32.png`、`favicon-64.png`、`apple-touch-icon`（`icon-180.png`）、`manifest.webmanifest`、`theme-color`、`apple-mobile-web-app-title`。圖示放在 `daily/assets/icons/`，不要改圖。報告頁的路徑是 `../assets/icons/…`、`../manifest.webmanifest`；`index.html` 與 `method.html` 在 `daily/` 底下，路徑不加 `../`。
- **手機版（直式）**：`report.css` 在 600px 以下有專用規則，電腦版不受影響，不要為了手機去改電腦版樣式。
  - 3 欄以上的表格（必須有 `thead`）在手機上會自動變成直式卡片：第一欄當標題，其他欄依表頭顯示成「標籤＋內容」。所以**每張表都要有 `thead`，第一欄要放最能代表這一列的內容**（日期、名稱、項目）。
  - 不要在表格或段落放很長、不能斷行的字串（網址、長代碼）；必要時放在連結文字裡。
  - 交稿前用 `mobilecheck.py` 檢查一次（375px）：頁面不能左右捲動。

### 5.10 理性市場資訊（隱藏區塊，早報與午報都要有）

使用者自己看的市場資訊頁，放在新聞後面、頁尾前面（2026-11-26 起取代原本的「理性檢查」，情緒對照、自我檢查那些內容都不再寫）。目的是綜合近期（約 1–4 週）的資訊，用數字講清楚：**現在哪些產業強、哪些弱、為什麼，強勢產業裡哪些股票特別突出、原因是什麼，弱勢產業有哪些特別的股票、哪些要注意**；債市、匯市、商品視市場狀況寫。台股、美股都要。只寫事實與 AI 的判斷，不寫操作指令或推薦語氣：「買進、賣出、加碼、減碼、布局、進場、出場、逢低承接、獲利了結、目標部位、停損價、首選、值得買、看好某股」都不可以出現。

- **隱藏機制：** 主分頁按鈕 `<button class="vault" data-tab="am-intel|pm-intel">理性市場資訊</button>`（放在新聞按鈕後面），分頁 `<section class="panel vault" id="am-intel|pm-intel">`。`report.js` 處理：在頁面上依序輸入密碼（`VAULT_CODE`）就開啟，瀏覽器以 localStorage 記住；手機可連點刊頭最上方小字 5 下輸入；首頁刊頭顯示「隱藏權限已開啟」與「關閉」按鈕。未開啟時 `.vault` 一律不顯示（含列印、網址直接指到該 id）。舊報告的「理性檢查」分頁保留不改。**範本還是舊版時**（範本報告裡有 `am-check`／`pm-check`）：把那個按鈕和整個分頁刪掉，照本節新寫 `am-intel`／`pm-intel`，不可以沿用舊內容；`residue.py` 跑完再用 `grep -c 'am-check\|pm-check\|情緒和事實' 新報告` 輸出 0 就是通過（結束碼 1 是正常的）。
- **資料基準（數字一律用腳本，省時間也省 token）：** 台股用 twdata.py「3a. 類股近 5、20 個交易日」「成交金額前 100 名的近 5、20 個交易日漲跌」，加上三大法人、外資買賣超前 10 名與融資；**台股個股只從這些腳本清單挑**，某個強弱產業在清單裡沒有個股，就寫一句帶過，不另外手動抓價。美股用 `usdata.py strength` 的輸出（`strength-us-YYYYMMDD.md`：產業 ETF、AI 與大型科技股）；強弱產業的代表個股不在表裡時，用 `usdata.py strength --cutoff … --extra "代號=名稱,…"` 補數字，不可抄網頁報價。債市、匯市、商品用 usdata.py 的殖利率與週漲跌。腳本沒有的（強弱的原因、個股的財報、訂單、法說、評等變動）由台灣、美國研究子代理順便查（只查新進與有新消息的列，見下一項；寫在筆記的「強弱產業」一節），不另開子代理。
- **延續與變化（近 20 日的強弱不會每天變）：** 這一頁是「接著上一份改」，不是每天重寫。
  - 起點：早報的台股表接最近一份午報、美股表接最近一份早報；午報的台股表接當天早報，美股表直接沿用當天早報。找不到上一份的理性市場資訊（第一次、範本還是舊版、或前一份沒出）就全部當「新進」完整寫。
  - 每張表加「變化」欄：`新進`、`維持`、`轉強`、`轉弱`、`移出`（移出的列留一天，寫一句原因，下一份就刪）。
  - **進出要有門檻，避免天天換：** 產業在 3a（或 strength）的近 20 日相對大盤排進前 3（後 3）才列入強勢（弱勢），掉出前 5（後 5）才移出；個股連續兩份報告不在腳本清單、或原因已經不成立才移出。
  - 「維持」的列：數字照腳本更新，原因沿用上一份的文字與來源，不重新搜尋；只有新聞窗口裡出現和它有關的新消息才改寫。研究子代理只查「新進」與「有新消息」的列（平常台美各 0–5 次搜尋，不必用滿）。
  - **週一早報全面重查**一次（每列的原因與來源都重新確認、刪掉過時的），其他天只做增量。
  - 查核員只逐句核對「新進」「轉強」「轉弱」與改寫過的列；「維持」的列只核對數字。
- **固定內容（不用子分頁，依序用 h3 分段）：**
  1. 摘要（第一層）3–4 句：**第一句寫和上一份比的變化**（例：「和 11/26 午報比：台股強勢新進通信網路、半導體移出；美股沒有變化」；沒有變化就直說「強弱排序和上一份相同」）；接著台股、美股目前最強與最弱的產業各一句（附近 20 日相對大盤）與主因；債市與匯市一句；最後一句固定「依截止前公開資料整理；列出個股是因為表現或事件突出，不是推薦，也不是買賣建議」。
  2. **台股**、3. **美股**，各四張表：
     - **強勢產業**（2–3 個）：產業、近 5 日／近 20 日（括號寫相對大盤百分點）、強的原因（事實＋來源連結）、什麼事實出現會讓它轉弱（條件式寫法，不寫「還會漲」這類預測）。
     - **強勢產業的突出個股**（每個產業 1–3 檔，台美各最多 8 檔）：個股（代號）、產業、近 5 日表現與成交金額或法人動向、突出的原因（附來源）、要留意的事（風險事件，不寫個股還會不會漲）。
     - **弱勢產業**（2–3 個）：欄位同強勢產業，寫弱的原因。
     - **弱勢產業的特別個股與要注意的股票**（台美各最多 6 檔）：個股（代號）、類型（「特別弱」`.dn`、「逆勢抗跌」`.up`、「要注意」`.flat`）、表現、原因（例：財報或財測下修、法人連續賣超、融資偏高、處置或全額交割、訴訟與監管）。
  4. **債市、匯市與商品**：只寫近期有明顯趨勢或變化的 2–5 項（項目、近期走勢與資料日期、原因、對台美股市的含意）；沒有明顯變化就寫一句「這段期間沒有明顯趨勢」。
  5. 表下一行說明：「強弱以近 20 個交易日相對大盤為主、近 5 日為輔，再加上消息與籌碼；台股個股漲跌未調整除權息」。結尾 `.callout.warn` 一句：資料截止時間、AI 判斷可能出錯、不是買賣建議也不是推薦，AI 不是持牌投資顧問。
- **判斷原則：** 強弱看近 20 日相對大盤（大盤大跌時「跌得少」也算相對強，要寫清楚是相對），單日大漲大跌不足以定強弱。突出個股一定要寫具體原因，只是漲很多不夠；找不到原因就寫「查無明確消息，可能是資金輪動」，不可以自己推想成消息。要和同一份報告其他分頁（市場頁、專題、觀點）的判斷一致。
- **午報：** 台股部分用當天 15:30 的腳本重新整理；美股在 15:30 前沒有新交易，沿用當天早報的美股表（寫明「沿用 MM/DD 早報」），只有 07:00 後有重大新消息的列才改；債市與匯市更新新台幣、日圓與亞洲時段的變化。當天沒有早報時，先跑 `usdata.py strength --cutoff "D 15:30" --out _research/D`，美股照早報格式整理。
- 數字與事實照時間界線與來源規則，和其他分頁一樣要經過查核（數字查核員核對表中數字，內容查核員逐句核對原因與來源）；`reports.js`、首頁卡片不放這一頁的內容。
- 週報另有隱藏區塊「AI 成績單與檢討」（同一套隱藏機制，內容見 `daily/RULES-WK.md` 第四節）。

## 六、寫作標準

### 6.1 摘要的長度與內容

| 位置 | 長度 | 必須包含 |
| --- | --- | --- |
| 總覽摘要 | 一句粗體結論＋ 6–8 條，每條 2–3 句 | 昨夜今晨（週一為週末）發生了什麼、全球重大事件、台灣與美國的含意、觀點變化、本週關鍵事件 |
| 個別市場總摘要 | 台灣、美國各 2–3 句＋相對強弱＋其他市場一句 | 誰強誰弱、為什麼 |
| 單一市場摘要 | 5–7 條，每條 1–3 句 | 盤勢、籌碼、總經、觀點、風險、接下來 |
| 子分頁摘要 | 4–6 句 | 結論、原因與數字、變化、風險、要看什麼 |
| 專題摘要 | 4–6 句 | 事件、為什麼重要、對市場的影響、AI 判斷 |
| 總經摘要 | 6–8 條 | 台灣、美國、情境判斷、利率美元、油價、信用、其他經濟體 |
| 台灣總經、美國總經 | 一句結論＋ 6–7 條 | 成長、通膨、央行、利率匯率、對股市的含意 |

摘要寧可多一點具體數字和原因，也不要只寫一句結論。

### 6.2 分析與歸納（早報、午報都適用）

- **不要只丟資訊。** 每張數據表後面都要接一段「解讀」或「歸納」：這些數字合起來說明了什麼、和昨天或市場預期比如何、對台美市場的含意。
- 每個區塊結尾要有「所以呢」：AI 判斷、信心、接下來要看什麼。
- 多條新聞或數據指向同一件事時，要歸納成一個結論，不要逐條平鋪。
- 意見分歧時（例如法人看多看空都有），寫出雙方論點，再說 AI 比較認同哪一邊、為什麼。

### 6.3 其他寫作規則

- 報告中分析者一律稱「AI」，不用第一人稱「我」。例如「AI 認為」「AI 判斷」「市場怎麼看 vs AI 怎麼看」「AI 分析」。

- 每條重點都要有「所以呢」：對哪個市場、往哪個方向、多大程度。
- 數字帶單位與日期；百分比和點數至少給一個。
- 專有名詞第一次出現時簡單說明。
- 不用誇張字眼、不堆形容詞、不用表情符號。
- 漲跌一律標顏色 class。機率旁註明「主觀」。
- 事實與判斷分開寫；判斷要說出理由。
- 研究筆記（`_research/`）不公開，報告裡不可叫讀者去看研究筆記；讀者需要的數字要直接放在報告裡（圖上沒標全的數字，就在圖下補一張表）。

## 七、reports.js 格式與網站首頁

- 網站名稱：**市場日報**。首頁標題「市場日報」右邊同一行、空約兩三個字的距離，放小字「台灣、美國為主，兼顧全球重大事件」（`div.ttl` 裡的 `span.tsub`）。首頁刊頭下方是三種報告的時間（`div.sched`，三欄並排，手機改直排），每欄一行時間＋一行小字（`span.sd`）：早報「平日 07:00 截止｜約 07:45 上線」／「台美同等權重：隔夜美股、總經、行事曆，專題是當下大事」；盤後午報「平日 15:30 截止｜約 16:15 上線」／「台股收盤的盤勢與籌碼、更新觀點，台美各一檔個股深度分析」；週報「週六 10:00 截止｜約 10:45 上線」／「一週回顧、下週展望與深度主題」。下面是「早報」「盤後午報」「週報」三張卡並排（寬度不足 1000px 時改直排），顏色區分（早報深藍、午報赭色、週報青綠）。**首頁卡片不放長摘要**：只有標籤與日期、標題（`headline`）、2–3 條短重點（`reports.js` 的 `keys`，每條約 25 字內）、一行式立場（短／中／長）與閱讀按鈕；讀者一定會點進報告，首頁只講重點。卡片的立場行：早報卡、週報卡顯示台灣、美國各自的短中長期；午報卡只顯示台股短期（由 `views` 欄位決定，午報只填 `tw.s`）。最下面是清單，用分頁切換「所有早報／所有盤後午報／所有週報」（`div.arc-tabs`，記住上次選的分頁）；每列：主題（`headline`）一行，太長自動截斷，滑鼠移過顯示全文；下方小字是立場（早報、週報顯示台、美短期，午報顯示台股短期）。首頁不放 Analytics Hub 連結。首頁標頭右下有小字連結「分析 Prompt 說明」，指向 `method.html`；該頁會直接讀取 `RULES.md` 與 `RULES-PM.md` 顯示，所以規則改了就自動同步，不用另外改頁面。
- 早報檔名 `reports/YYYY-MM-DD.html`，`kind: "am"`；午報檔名 `reports/YYYY-MM-DD-pm.html`，`kind: "pm"`；週報檔名 `reports/YYYY-MM-DD-wk.html`，`kind: "wk"`。上一份／下一份只在同一種之間切換。
- 每筆要有 `keys`：2–3 條短重點（每條約 25 字內，首頁卡片顯示）；`points`：3–5 條較完整的重點（保留，首頁目前不顯示）。

### reports.js 欄位

```js
{
  id: "2026-11-16", kind: "am", date: "2026-11-16", weekday: "一" /* 中文 */, edition: "早報",
  keys: ["短重點一", "短重點二", "短重點三"],   // 首頁卡片，2–3 條，每條約 25 字內
  points: ["重點一", "重點二", "重點三"],
  headline: "一句話標題",
  summary: "兩到三句摘要",
  views: {
    tw: { s: "lbear", m: "lbear", l: "lbull" },
    us: { s: "...", m: "...", l: "..." }
  },
  stats: "加權 xx｜S&P 500 xx｜費半 xx｜美債 10 年 xx｜新台幣 xx"
}
```

立場代碼：`bull` 偏多、`lbull` 中性偏多、`neutral` 中性、`lbear` 中性偏空、`bear` 偏空。

## 八、view-log.md 格式

檔頭固定一句「每份早報、午報產出後更新，最新的在最上面。」每份早報在最上面加一節，標題固定：

`## YYYY-MM-DD（X）早報（資料截至 07:00；新聞窗口 MM/DD 07:00–MM/DD 07:00）`

內容依序：

1. 立場表（台灣、美國 × 短中長期，含信心；日本、南韓只記短期）
2. 情境機率：台灣、美國各期的樂觀／基本／悲觀，以及總經四種情境（5.6 `mc-scn`）
3. 核心判斷（3–5 條）
4. 關鍵數字（供隔天比較，口徑見 4.7「口徑固定」）
5. 台股止穩訊號狀態
6. 翻轉條件
7. 待追蹤事件（日期、台北時間）
8. 明天要補查的；研究筆記路徑（`_research/YYYY-MM-DD/`）
9. **今天 07:00 之後已知的事件**：寫報告時如果已經是 07:00 以後，把當下已知但不能寫進今天報告的事列在這裡，給午報與隔天早報當線索，使用前仍須重新查證。
10. **製作時間**（一行，給週報檢討上線時間）：`開始 HH:MM｜usdata HH:MM｜子代理交齊 HH:MM｜開查核 HH:MM｜複核完 HH:MM｜上線 HH:MM｜最慢：哪一步`

當天午報會在這一節的第 9 項前面加上「午報更新」小節（格式見 RULES-PM.md 第七節）。當天沒有早報時，午報另開一節（見 RULES-PM.md 第七節）。

## 九、排程

- **只在週一到週五**的 06:30 左右（台北）由 Claude 桌面版排程任務開始準備，資料截止仍是 07:00。排程設定是 06:30，系統固定會延遲約 10 分鐘，實際約 06:40 開始。App 沒開時會在下次開啟時補跑。週六、週日不出報告。
- **報告日期＝觸發排程的那個平日。** 不補做過去的日期：昨天的早報沒出，今天不補，只在今天的報告裡照常和最近一份報告比較。
- **補跑：** 實際執行時已經晚於 07:00，仍以 07:00 為時間界線寫報告；07:00 之後的資訊放進 view-log 第 9 項。**開始時早於 06:20（前一天漏跑的補跑）或已晚於 14:00（避免和 15:00 開始準備的午報重疊）就不產出**，回報「早報略過」與原因。
- **排程中不可使用任何會跳出「允許」視窗的工具：** 不可開預覽伺服器（`preview_start`、`.claude/launch.json`）、不可用瀏覽器面板或 Chrome 工具、不可問使用者問題。這些都要人按允許，排程時沒人在，整份報告會卡住（2026-11-18 早報就卡在啟動預覽伺服器）。要看網頁一律用 curl 或 Python 腳本；手機寬度用 `mobilecheck.py`（5.9）。
- **和午報同時執行：** 用執行鎖（`daily/tools/runlock.py`）避免；萬一同時執行，照步驟 0 第 3 項檢查，commit 時只帶自己的檔案，rebase 衝突照步驟 6 處理。
- 週一的報告要涵蓋整個週末：新聞窗口從上週五 07:00 起算，總覽要有「週末發生了什麼」，並加上本週展望。
- 平日遇到台灣或其他市場休市照常產出，休市的市場行情標明為上一交易日（判斷方法見 4.7「休市判斷」）。
- **過渡說明：** 11/16 早報是特例，以 11/16 08:00 為時間界線。11/17 早報起一律 07:00；11/17 的新聞窗口從 11/16 07:00 起，和 11/16 早報重疊的 07:00–08:00 這段靠去重清單處理。
