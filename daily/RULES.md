## 一、最高原則

1. **時間界線：報告一律站在當天台北時間 07:00 的角度寫。**
   - 檔名日期 D 的報告，只能使用 D 日 07:00 以前已經公開的資訊。
   - 07:00 以後才發生或才公布的事（例如當天台股、日股、韓股的盤勢，當天 07:50 以後的數據），不寫進當天早報：台股與當天亞洲盤勢由當天 15:30 的盤後午報處理，其餘留給隔天早報。
   - 判斷方法：看來源的發布時間，換算成台北時間。不確定發布時間的，不用。
   - 早上 07:00 時各市場狀態：美股剛收盤（台北 05:00；美國夏令時間為 04:00）、歐股前一晚收盤、台日韓是前一交易日收盤。日本 07:50 公布的數據不能用，留給午報。
2. **即時性優先。** 所有數字都是當次重新查到的。不可沿用前一天報告的數字當成今天的，也不可用模型記憶裡的數字。模型的知識截止日遠早於現在，價格、利率、人事、政策一律以搜尋結果為準。差一兩天的資訊在這個市場可能已經過時。
3. **每個數字都有出處和時間。** 表格要標資料日期；新聞要附原文連結。
4. **查不到就說查不到，不可編造。** 數字、引述、連結都必須是實際看到的。連結必須是搜尋結果或抓取頁面上出現過的 URL。
5. **事實和判斷分開。** 機率一律標明是主觀估計。
6. **觀點要連續，改變要交代。** 每天和前一天比較：維持、上修或下修，並說明是哪個新資訊造成的。
7. **正反並陳，寫出翻轉條件。**
8. **只在週一到週五出報告；新聞依窗口收錄。** 週二到週五：前一天台北 07:00 到當天 07:00（24 小時）。週一：上週五台北 07:00 到週一 07:00（涵蓋整個週末）。不和前一份報告重複。詳見 5.8。
9. **不確定的事寫在該段裡，不另開區塊。** 例如「台積電 ADR 溢價（待今晚美股開盤確認）」或「這個數字只有單一媒體來源」。報告不設「資料限制與更正」區塊。對前一天報告的更正，寫在相關段落，用一句「更正：昨天寫 X，正確是 Y」。
10. **不是投資建議。** 頁尾固定附免責聲明。

## 二、市場範圍

- **主要市場（完整分析）：台灣、美國，兩者在早報中權重相同。** 篇幅、分析深度、觀點（短中長期、情境、翻轉條件）、總經頁都要對等；總覽與首頁也要同時呈現台美兩邊的觀點，不能只寫台股。每天都有完整的市場頁（盤勢、總經、短中長期觀點），總經頁也是台灣、美國分開各自詳細分析。
- **次要市場（簡要帶過）：日本、南韓、中國與香港、歐洲、印度與東南亞。** 放在「個別市場 → 其他」，每個市場一小段＋一張小表，只寫和台美有關的部分。日本、南韓另給一個短期立場標籤。不要在次要市場花太多篇幅。
- **全世界的重大事件不限國家都要寫。** 戰爭、政變、選舉、天災、重大政策、央行意外動作、大型企業事件等，只要可能影響市場，都要放進新聞，重大的要進專題，並在「總經 → 全球主線」寫傳導路徑。

## 三、每日作業流程

### 步驟 0：讀檔與前置檢查（必做）

1. 讀本檔全文。
2. **確認日期：** 用系統時間確認今天日期與星期。報告日期 D ＝ 觸發排程的那個平日（補跑規則見第九節）。確認 D 與前一個美國交易日是否休市（4.7「休市判斷」）。
3. **同步與防重複：** 先 `git status`，再 `git pull --rebase --autostash origin main`。
   - `daily/reports/D.html` 已存在、或 `reports.js` 已有 D 的早報：停止，回報「已產出」。
   - `reports.js` 或 `view-log.md` 有不是自己改的未 commit 改動：代表另一份報告正在產出。不要覆寫，commit 時也不要把它們帶進去（見步驟 6）。
4. 讀 `daily/state/view-log.md` 最上面一節：前一份的立場、機率、關鍵數字、翻轉條件、待追蹤事件、「明天要補查的」、「午報更新」、「之後已知的事件」。
5. **讀最近一份午報**（`reports/` 裡最新的 `*-pm.html`）。把它對台股觀點的更新、情境與翻轉條件當成今天的起點。如果它的日期早於最近一份早報（例如前一天午報沒出），改以最近一份早報＋view-log 為起點。
6. **讀最近一份早報**（`reports/` 裡最新、檔名不含 `-pm` 的 HTML）。它是今天的版型範本，沿用它的 HTML 結構和 class（第五節有完整規格）。
7. **建立去重清單：** 把最近一份早報與最近一份午報的所有新聞標題（`span.n-t`）列出來，交給新聞子代理（規則見 5.8）。

### 步驟 1：蒐集資料

同時開 4 個研究子代理平行蒐集，各自把結果寫成 Markdown，固定放在 `C:\Users\User\Desktop\news\_research\YYYY-MM-DD\`（本機留存，不進 git）。檔名固定：`tw.md`、`us.md`、`global.md`、`news.md`。每個子代理的指示都要包含：

- 今天日期與 **07:00 時間界線**，以及「所有內容來自搜尋結果，不可用記憶」。
- 每個數字和事實附來源 URL、發布時間；區分「已確認（官方或兩個獨立來源）」與「單一來源」；查不到寫「查無」。
- 新聞每則要有：中文標題、原文標題、3–5 條中文重點（含數字、人名、日期）、2–4 句分析（對台美市場的影響、時間尺度、後續觀察）、URL、發布時間（原文時區與台北時間）、可信度。格式對應 5.8。

- `https://www.twse.com.tw/rwd/zh/fund/TWT38U?response=json&date=YYYYMMDD`（外資個股）
- `https://www.twse.com.tw/rwd/zh/marginTrading/MI_MARGN?response=json&selectType=MS&date=YYYYMMDD`（融資融券）
- 期交所三大法人期貨：`https://www.taifex.com.tw/cht/3/futContractsDate`（頁面表單選日期，`queryDate=YYYY/MM/DD`）

- 櫃買指數：櫃買中心官網的每日指數資料；網址常改版，抓不到時用中央社或鉅亨網的收盤報導，並標「非官方來源」。

期交所頁面是表單查詢，參數以頁面實際表單為準；抓不到時用中央社、鉅亨網的盤後報導，並標來源。

加權指數均線要自己算：抓近 13 個月的 FMTQIK，算 5、10、20、60、120、240 日均線（口徑見 4.7「口徑固定」）。不要引用媒體的均線數字。

**三大法人用修正後的數字：** 證交所三大法人在收盤後約 15:00 先公布初版，晚間可能修正。早報引用前一交易日數字時一律用修正後的版本；若和前一份午報（初版）不同，在相關段落註明「午報引用的是 15:30 前的初版，修正後為 …」。

來源優先順序：官方（交易所、央行、統計機關）＞通訊社與主流財經媒體（Reuters、Bloomberg、CNBC、WSJ、FT、Nikkei、韓聯社、中央社、經濟日報、工商時報、鉅亨網）＞其他。部落格、Substack、彙整站只能當線索；不得已引用時要在文中標「非官方來源」。

### 步驟 5：查核（必做，不可省略）

報告寫完後，開一個**獨立的查核子代理**（不要讓寫報告的同一個脈絡自己查自己）。指示固定用下面的範本，把 `{ }` 換成實際值：

```text
你是獨立查核員。只回報問題，不要修改任何檔案。
- 報告：C:\Users\User\Desktop\news\daily\reports\{D}.html
- 研究筆記：C:\Users\User\Desktop\news\_research\{D}\（tw.md、us.md、global.md、news.md）
- 前一份早報：{路徑}；最近一份午報：{路徑}
- 觀點紀錄：C:\Users\User\Desktop\news\daily\state\view-log.md（最上面一節是今天新寫的）
- 首頁索引：C:\Users\User\Desktop\news\daily\reports.js（第一筆是今天新寫的）
- 時間界線：台北 {D} 07:00；新聞窗口：台北 {起} 至 {訖}
所有數字都要重新搜尋或抓官方資料核對，不能只比對研究筆記。
連結打不開（403、付費牆、被擋）時標「無法確認」，不要當成錯誤。
逐項檢查：（列出下面 1–9 項）
回報格式：錯誤（必改）／過時（必改）／無法確認（加註或刪除），每項寫位置、原文、正確值與來源。
```

查核項目：

1. 逐一核對報告裡的每個數字：指數、漲跌幅、法人買賣超、利率、匯率、商品、總經數據、央行利率與會議日期、財報預期。每個至少回到一個來源確認；關鍵數字（主要指數收盤、法人買賣超、政策利率）要兩個來源或官方。
2. 檢查時間界線：任何 07:00 以後才公布的資訊都要刪掉。
3. 檢查即時性：每個數字是不是最新的。例如報告用了兩天前的殖利率，但其實昨晚已有新的收盤，要換掉。
4. 驗算：漲跌點 ÷ 前收 = 漲跌幅；距離百分比；情境機率加總 100%；日期與星期是否對得上。
5. 檢查每一則新聞：發布時間是否在新聞窗口內、是否和去重清單重複（5.8）、連結是否有效、中文重點與原文是否相符。
6. 檢查專題的視覺（時間線、長條圖等）上的數字和日期是否和內文一致、是否正確。
7. 檢查和前一份午報、前一份早報的一致性：數字有沒有矛盾、觀點變化有沒有交代原因、比較基準是否正確（4.3）。
8. 檢查 `reports.js` 第一筆（points、headline、stats、views）與 view-log 最上面一節（立場、機率、關鍵數字）是否和報告內文一致。
9. 檢查範本殘留：日期、時間、`.asof`、新聞窗口文字、頁尾、`<title>` 是否都是今天的（5.9）。

主筆另外自行確認：用語都是「AI」不是「我」；每張表都有 `thead`；`<head>` 有圖示與 manifest；手機寬度檢查（方法見 5.9）。

主筆依清單修正（報告、reports.js、view-log 都要改）後才能發布。修正的內容不需要在報告裡另外交代，除非是更正前一天的報告。

```bash
cd /c/Users/User/Desktop/news
git status --short
git add daily/reports/YYYY-MM-DD.html daily/reports.js daily/state/view-log.md
git commit -m "daily: YYYY-MM-DD 早報" -m "Co-Authored-By: Claude <noreply@anthropic.com>"

```

- 只 add 自己這份報告的三個檔案（報告 HTML、`reports.js`、`view-log.md`）。`git status` 若出現其他未 commit 的改動（例如規則檔），不是這次產出的就不要帶進去。

- 推送後等 1–2 分鐘，用 curl 確認 `https://finatticus.github.io/structuredproductanalysis/daily/reports/YYYY-MM-DD.html` 回應 200。不是 200 就每 2 分鐘再試一次，最多 5 次；還是不行就在回報裡寫明。

## 四、分析框架

### 4.1 時間尺度

| 尺度 | 期間 | 主要驅動 | 主要依據 |
| --- | --- | --- | --- |
| 短期 | 1–2 週 | 事件、籌碼、情緒、技術面 | 行事曆上的催化劑、期貨選擇權部位、融資、均線與缺口、波動率 |
| 中期 | 1–3 個月 | 央行路徑、獲利修正、資金流向、估值 | 利率期貨定價、獲利預估修正、外資動向、信用利差 |
| 長期 | 6–18 個月 | 景氣循環、產業趨勢、獲利成長、估值水位、結構性風險 | GDP 與獲利預估、資本支出週期、融資條件、政策與地緣 |

### 4.2 每個尺度都要檢查的六個面向

1. **政策與利率**：央行在升、降還是觀望？市場定價和央行說法有沒有落差？
2. **總經與獲利**：數據在加速還是減速？企業獲利預估上修還是下修？
3. **估值**：本益比相對歷史和相對利率在哪裡？已經反映多少？
4. **資金與籌碼**：誰在買、誰在賣？槓桿高不高？
5. **情緒與技術**：恐慌還是貪婪？關鍵價位在哪？
6. **事件與地緣**：行事曆上有什麼？尾部風險是什麼？

### 4.3 立場、信心與機率

- 五級立場：**偏多／中性偏多／中性／中性偏空／偏空**。
- 信心：高／中／低。
- 與前一日比較：維持、上修、下修，附一句原因。第一份報告寫「首份」。
- **比較基準：** 台股短期和「最新的立場」比：最近一份午報有更新就和午報比，否則和前一份早報比，並在括號註明比較對象，例如「維持（對照 11/16 午報）」。台股中長期與美國各期，一律和前一份早報比。
- 情境表至少三種（樂觀／基本／悲觀），每種有觸發條件、可能區間、主觀機率，加總 100%。
- 翻轉條件：「看到什麼 AI 會改變看法」，要寫具體價位或數據。
- 機率是主觀估計。前後兩天的機率變動要有理由；沒有新資訊就不要為了變而變。

### 4.4 利空利多的分類

遇到重大事件先分類，再判斷消退速度：

- **事件面**（人事、單一公司、單一數據）：通常幾天到幾週消化。
- **政策面**（監管、關稅、選舉）：漸進、持續數月。
- **資金面**（利率、流動性、信用、去槓桿）：最慢，最影響估值。
- **基本面**（需求、獲利、景氣）：決定長期方向。

多層疊加時要分開寫。

### 4.7 分析方法細則（怎麼算、怎麼判斷）

**估值**

- 本益比要註明口徑：歷史（過去四季獲利，金管會、證交所公布的多為此口徑）或預估（未來 12 個月，市場評論多為此口徑）。兩者不能混用、不能直接比較。
- 股票風險溢酬（簡算）＝ 1 ÷ 預估本益比 − 10 年期公債殖利率。接近 0 或為負，代表股票相對債券沒有吸引力，本益比難以擴張，指數只能靠獲利成長上漲。
- 估值高低要同時和三個基準比：自身歷史平均、利率水準、同業或其他市場。
- 台股另看股價淨值比與現金殖利率；權值股占比高（台積電逾四成），要拆開看「台積電」與「其他」。

**技術面（台股）**

- 均線一律用證交所 FMTQIK 的每日收盤自己算（5、10、20、60、120、240 日），不用媒體數字。
- 指數相對位置 ＝ 收盤 ÷ 均線 − 1；距關鍵價位 ＝ 價位 ÷ 收盤 − 1。
- 缺口：向上缺口是今日低點 ＞ 前一日高點；向下缺口是今日高點 ＜ 前一日低點。回補是之後的價格碰到缺口另一端。
- 回吐比例 ＝（反彈高點 − 現價）÷（反彈高點 − 起漲低點），註明用收盤或盤中高低點。
- 量價：大跌爆量（恐慌換手）和大跌量縮（跌停鎖死、賣壓未釋放）意義不同，要分開判斷。
- 均線排列：月線（20）與季線（60）交叉、季線與年線的方向，用來判斷中期趨勢。

**籌碼（台股）**

- 外資現貨：看當日、連續天數、當月累計；扣除 ETF（尤其主動式 ETF）的套利與短線部位，才是對個股的真實方向。
- 外資台指期淨未平倉：看方向與變化量。大跌時外資空單沒有增加，是「沒有加空」的訊號；空單創高並持續增加，才是轉空的訊號。投信的期貨多單多半是 ETF 避險，不能把外資空單全部當成看空。
- 結算週：看近月與次月未平倉分布（轉倉進度）、逆價差（用最後成交價與結算價各算一次）。
- 自營商分「自行買賣」與「避險」：避險部位是權證與 ETF 造市的被動調整，跌愈多賣愈多，會放大波動。
- 融資：餘額變化、整戶維持率（金管會口徑與媒體口徑不同）。融資在反彈中增加＝散戶追價，之後下跌會變賣壓。
- 判斷「去槓桿」或「轉空」：同時看外資期貨、成交量、跌幅結構（集中或全面）、投信動向、匯率。三項以上偏同一方向才下結論。

**利率、匯率與資金傳導**

- 美債 10 年殖利率上升 → 壓低全球股票估值，高本益比股受影響最大。
- 美台利差擴大、美元走強 → 新台幣偏弱 → 外資匯出壓力；央行進場與出口商拋匯是支撐。
- 日圓急升 → 日圓套利交易平倉 → 全球風險資產波動。
- 油價 → 整體通膨（2–3 個月）→ 核心通膨（再落後 3–6 個月）→ 央行路徑。

**情境與機率**

- 基本情境通常 40–50%，樂觀與悲觀各 20–35%，加總 100%。
- 機率的變動要對應到具體的新資訊；沒有新資訊不變。單日變動超過 15 個百分點，必須是重大事件，並寫明原因。
- 立場要和情境機率一致：例如悲觀情境機率高於樂觀，立場不應是偏多。
- 翻轉條件要事先寫好，下一份報告先檢查條件是否觸發，再決定是否改立場（不能事後找理由）。

**專題的選擇**

- 優先順序：會在 1–2 週內影響台美市場方向的事件 ＞ 會改變中期判斷的政策或數據 ＞ 長期結構議題。
- 同一題目連續出現時，只寫新的發展與判斷的變化，不重抄背景。

**新聞的選擇**

- 必收：會影響台美市場的政策、央行、重要數據、權值股與大型企業事件、地緣衝突、全球重大事件（不限國家）。
- 不收：重複的稿件、沒有新資訊的評論、時間窗外的稿件。
- 同一事件有多篇報導時，選最原始、最權威的一篇，其餘只用來核對。

**來源與可信度**

- 分三級：官方與交易所 ＞ 通訊社與主流財經媒體 ＞ 二手整理、部落格、Substack。第三級只能當線索，引用時標「非官方來源」。
- 只有一個來源的數字標「單一來源」；兩個來源不一致時，兩個都寫，並說明採用哪一個與原因。
- 證交所等官方資料可能在當天稍晚修正（例如三大法人初版與確定版），引用時以報告時間界線當下公布的版本為準，並註明。

**口徑固定（每天一樣，才能前後比較）**

- 外資台指期淨未平倉：只算「臺股期貨」（TX）的口數，不含小型台指、微型台指。要提小台時另外列。
- 成交值：證交所 FMTQIK 或 MI_INDEX 的「總計」成交金額（含 ETF 等），單位億元。
- 新台幣：台北外匯經紀公司 16:00 收盤價（中央社、鉅亨網報導的收盤價即此口徑）。
- 均線：每日收盤價的簡單平均（不是加權或指數平均）；資料不足 N 日時不算。
- 三大法人：證交所 BFI82U，單位億元（官方為元，除以 1 億，取到小數兩位）。外資用表上「外資及陸資（不含外資自營商）」這一列（和媒體報導的口徑相同）；「外資自營商」通常為 0，不為 0 時另外註明。自營商分「自行買賣」與「避險」兩列；三大法人合計用表上「合計」列。和媒體數字不一致時，以官方為準並註明。

**休市判斷**

- 台股：看證交所「市場開休市日期」表；再確認 FMTQIK 是否有該日的資料。遇颱風等臨時休市，看行政院人事行政總處與證交所公告。
- 台股休市日照常產出早報，台股行情標明為上一交易日。
- 美股前一交易日休市時，早報刊頭寫「美股：MM/DD 休市」，行情表用上一個交易日的收盤並標日期。

## 五、報告版面標準（每份都一樣）

### 5.1 原則

- **分頁，不要一頁拉到底。** 頂部一排主分頁；「個別市場」裡再分市場，市場裡再分子分頁。一次只顯示一個區塊。
- **每個區塊最上方都有摘要，而且摘要要夠詳細。** 讀者只看摘要就要能知道：結論是什麼、為什麼（附關鍵數字）、和前一天比有什麼變化、最大的風險、接下來要看什麼。見 6.1 的長度標準。
- 投行研究報告風格：淺色、白底、深藍主色、細線表格、方角、無表情符號、無漸層。
- **摘要分三層，外觀要看得出輕重**（CSS 已自動處理，只要放對位置）：
  - 第一層：分頁最上方的總摘要（`section.panel > .summary`）。淺藍底、深藍粗上框，標題字最大。標題用「摘要」或「專題總摘要」。
  - 第二層：子分頁的摘要（`.subpanel > .summary`）。淡青綠底、青綠左粗線。標題用「本頁摘要」「專題摘要」「結論」。
  - 第三層：子分頁內再分的子分頁摘要（`.subpanel .subpanel > .summary`）。淡米色底、金色左細線，最輕。
  - 每層摘要都要有底色，不能和內文一樣是白底；摘要標題（`.summary-h`）字要夠大，後面接一條細線。
- **小標題與配色**（CSS 已處理，寫 HTML 時用對元素即可）：
  - `h3` 小標題和上一段之間要有明顯間距，左側有金色細條；不要把 `h3` 緊接在上一段文字後面而不分段。
  - 專題敘述的段落標題用 `div.essay` 裡的 `h4`（青綠色、下方細線）。
  - 配色只用四種：深藍（主結構）、青綠（摘要第二層、提示框、AI 看法）、金色（小標題、第三層摘要）、紅綠（漲跌）。琥珀色只用在警示（`.callout.warn`）。例外：午報的識別色赭色（CSS 變數 `--pm`）只用在首頁的午報卡片與午報清單。不要再加其他顏色。
- 先結論後細節；多用表格與條列；段落不超過 4 行。

### 5.5 專題

- 選當下最重要、最即時的 2–4 個事件，不限國家（只要可能影響台美市場）。不要選已經被市場消化完的舊題目。
- **專題是深入分析，不是數據表。** 每個專題要有 4–6 段、每段 2–5 句的敘述，把事情的來龍去脈、因果關係和AI 判斷講清楚；數據表是佐證，放在敘述後面。
- 專題分頁最上方：專題總摘要（每個專題 2–3 句，第一層）。
- **每個專題都要有視覺輔助，敘述保留不刪。** 文字負責講道理，視覺負責讓讀者不用自己拼湊。每個專題至少 2 個，依題目選適合的，不要硬塞：
  - **時間線**（`ol.timeline`）：事件有前因後果、有後續日程時用。已發生的事、重大節點（`li.key`）、利空（`li.bad`）、未來日程（`li.next`）用不同圓點區分。
  - **因果流程**（`div.flow`）：解釋傳導機制時用，例如「油價 → 通膨 → 升息 → 估值」，可加 `div.flow-back` 寫反向或解方。
  - **比較卡**（`div.cards3` 或 `div.cards2` 裡放 `div.ccard`）：有幾條路線、幾種方案、雙方籌碼時用。
  - **長條圖**（`div.bars`）：比較大小、前後變化、分項組成。正負都有時用 `div.bars.center`（中線為 0）。寬度是相對比例，要在 `p.viz-note` 寫單位、來源或「AI 主觀評估」。
  - **證據天平**（也是 `div.bars`）：判斷兩種解讀哪個較可能時用（例如「去槓桿 vs 轉空」）。每列一種解讀，`.bl` 寫「支持 A」「支持 B」「待確認」，`.bv` 寫項數或關鍵證據，顏色用 `.bf.teal`（支持 A）、`.bf.dn`（支持 B）、`.bf.gray`（待確認），寬度＝該列項數 ÷ 總項數。下方用 `p.viz-note` 列出每一項證據。
  - **對照表**：情境、關鍵數字、影響表維持用表格。
- 所有視覺都包在 `div.viz`（標題 `div.viz-h`），兩個並排用 `div.viz-grid`。圖上的數字要和內文、表格一致，也要經過查核。
- 視覺的 HTML 寫法從最近一份有該種視覺的報告複製，不要自己發明新 class。
- 每個專題一個子分頁，id 為 `th-英文短名`（例如 `th-nvda`、`th-rates`），固定結構：
  1. 專題摘要（第二層）：一句粗體結論＋ 3–5 句說明
  1.5 視覺輔助：最重要的一張（通常是時間線或因果流程）放在摘要後、敘述前；其他放在敘述後、「市場 vs AI」前
  2. 深入分析（`div.essay`，用 `h4` 分段，常見段落）：為什麼這件事重要／背景與脈絡；拆解關鍵機制（例如數字背後的意義、利潤往哪裡移動、誰受惠誰受害）；不同的可能路徑與各自的代價；尚未被市場注意的風險；對台灣、美國的傳導路徑
  3. 市場怎麼看 vs AI 怎麼看（`div.view-box`，`.mkt` 與 `.mine` 兩格）
  4. 關鍵數字或時間線表
  5. 情境與主觀機率
  6. 觀察清單（`.callout`）：具體指標與日期

### 5.7 行事曆

- 欄位：時間（台北）、市場、事件、**分析**。「市場」欄不換行（`td.nw`）。
- 每列加 `data-mkt`：`tw`、`us` 或 `other`；跨市場的事件可以寫多個，用空白隔開（例如 `data-mkt="us other"`）。分組列 `tr.grp` 不加。
- 頂部放篩選列：`<div class="fbar"><button data-filter="all">全部</button><button data-filter="tw">台灣</button><button data-filter="us">美國</button><button data-filter="other">其他</button></div>`。
- 「分析」要寫 AI 的看法：預期值與前值、市場目前怎麼定價、結果偏多或偏空時各會怎樣、AI 特別關注的細項。不要只寫「看是否升息」這種一句話。
- 重要事件（會改變觀點的）用 `tr.hl` 標示。

### 5.8 新聞

- **時間窗：** 週二到週五只收前一天台北 07:00 到當天 07:00（過去 24 小時）發布的新聞；週一收上週五台北 07:00 到週一 07:00（涵蓋週末）。窗外的新聞不放進新聞頁，需要的話可以在分析段落裡當背景提到。週一的新聞數量可以比平日多。
- **去重清單：** 最近一份早報與最近一份午報的所有新聞標題（步驟 0 第 7 項）。
- **不和前一份早報重複：** 前一份早報已收的事件不再列，除非有新的發展（那就只寫新的發展）。
- **和午報的關係：** 早報窗口 24 小時，會和前一天午報（07:00–15:30）重疊。午報已收的事件可以再收，但必須寫出之後的新發展，或從全球角度重新歸納；沒有新東西就不收。台股盤後細節不必重抄，直接引用午報的結論。
- **只要重點，但不能漏掉重要事件。** 不設最低數量，一般約 12–25 則。研究時要逐一掃過台灣、美國、日本、南韓、中國、歐洲、中東、俄烏、其他地區的重大事件（不限國家）、AI 與半導體、能源、央行，確認沒有漏掉。台灣、美國的新聞最多；日本、南韓只收重要的。
- 每則用可展開的卡片（`details.news`）：
  - 收合時看到：市場標籤、中文標題、來源與台北時間、一句話重點
  - 展開後看到：**重點**（3–5 條中文條列，含數字、人名、日期）、**分析**（2–4 句，對台美日韓的影響、時間尺度、後續要觀察什麼）、**原文連結**
- 頂部篩選列一律用 `div.fbar`（與行事曆共用同一套程式），按鈕固定為 `all` 全部、`tw` 台灣、`us` 美國、`gl` 全球、`jp` 日本、`kr` 南韓。每則新聞的 `data-mkt` 用這些值：日本、南韓以外的國家與跨國事件一律用 `gl`；一則新聞同時屬於兩個市場時可以寫兩個值，用空白隔開（例如 `data-mkt="us gl"`）。標籤 `span.n-mk` 寫主要的那一個市場。
- 外文新聞一律譯成中文整理，不要只放連結。

### 5.9 HTML 與 class 規格

檔案：`daily/reports/YYYY-MM-DD.html`，`<body data-report="YYYY-MM-DD">`。共用 `../assets/report.css`、`../assets/report.js`、`../reports.js`。最可靠的範本是最近一份早報。

- **`<title>`：** 「市場日報 早報 YYYY-MM-DD」；`<meta name="description">` 一句話寫當天重點。
- **刊頭：** kicker「市場日報 · 早報 · YYYY-MM-DD Mon」；`h1` 一句話標題；meta 寫「資料截至台北時間 MM/DD（X）07:00」與各市場資料日期（例如「美股：MM/DD 收盤」「台股：MM/DD 收盤」；休市寫「美股：MM/DD 休市」）。右上按鈕：「← 前一份早報」「首頁」「後一份早報 →」（`#prevBtn`、`#nextBtn`，由 report.js 自動連結）。
- **星期寫法：** kicker 用英文縮寫（Mon、Tue、Wed、Thu、Fri）；內文、meta、`reports.js` 的 `weekday` 用中文（一、二、三、四、五）。
- **頁尾：** `p.foot` 免責聲明，文字固定：「本報告由 Claude 依公開資訊整理分析，資料截至台北時間 YYYY-MM-DD 07:00。立場與機率為主觀判斷，不構成投資建議。」
- **分頁標題列：** 每個 `section.panel` 第一行是 `<div class="ph"><h2>名稱</h2><span class="asof">資料時間或範圍</span></div>`。
- **範本清理：** 複製最近一份早報後，先全文搜尋並換掉這些範本殘留，再開始寫：舊日期（`YYYY-MM-DD`、`MM/DD`、星期）、`<title>`、`description`、`data-report`、kicker、刊頭 meta、每個 `.asof`、新聞窗口文字、頁尾日期。11/16 早報是特例（以 08:00 為界），用它當範本時要把所有「08:00」改成「07:00」。查核第 9 項會再檢查一次。
- **手機寬度檢查方法：** 用 `.claude/launch.json` 的本機伺服器（`daily-site`，port 8765）開報告，視窗模擬 375×812，用 JavaScript 確認 `document.documentElement.scrollWidth <= 375`，並切到每個主分頁各看一次。

- **`<head>` 必須包含 APP 圖示與 manifest**（從最近一份報告整段複製）：`favicon-32.png`、`favicon-64.png`、`apple-touch-icon`（`icon-180.png`）、`manifest.webmanifest`、`theme-color`、`apple-mobile-web-app-title`。圖示放在 `daily/assets/icons/`，不要改圖。報告頁的路徑是 `../assets/icons/…`、`../manifest.webmanifest`；`index.html` 與 `method.html` 在 `daily/` 底下，路徑不加 `../`。
- **手機版（直式）**：`report.css` 在 600px 以下有專用規則，電腦版不受影響，不要為了手機去改電腦版樣式。
  - 3 欄以上的表格（必須有 `thead`）在手機上會自動變成直式卡片：第一欄當標題，其他欄依表頭顯示成「標籤＋內容」。所以**每張表都要有 `thead`，第一欄要放最能代表這一列的內容**（日期、名稱、項目）。
  - 不要在表格或段落放很長、不能斷行的字串（網址、長代碼）；必要時放在連結文字裡。
  - 交稿前用 375px 寬度檢查一次：頁面不能左右捲動。

## 六、寫作標準

### 6.1 摘要的長度與內容

| 位置 | 長度 | 必須包含 |
| --- | --- | --- |
| 總覽摘要 | 一句粗體結論＋ 6–8 條，每條 2–3 句 | 昨夜今晨（週一為週末）發生了什麼、全球重大事件、台灣與美國的含意、觀點變化、本週關鍵事件 |
| 個別市場總摘要 | 台灣、美國各 2–3 句＋相對強弱＋其他市場一句 | 誰強誰弱、為什麼 |
| 單一市場摘要 | 5–7 條，每條 1–3 句 | 盤勢、籌碼、總經、觀點、風險、接下來 |
| 子分頁摘要 | 4–6 句 | 結論、原因與數字、變化、風險、要看什麼 |
| 專題摘要 | 4–6 句 | 事件、為什麼重要、對市場的影響、AI 判斷 |
| 總經摘要 | 6–8 條 | 台灣、美國、情境判斷、利率美元、油價、信用、其他經濟體 |
| 台灣總經、美國總經 | 一句結論＋ 6–7 條 | 成長、通膨、央行、利率匯率、對股市的含意 |

摘要寧可多一點具體數字和原因，也不要只寫一句結論。

### 6.2 分析與歸納（早報、午報都適用）

- **不要只丟資訊。** 每張數據表後面都要接一段「解讀」或「歸納」：這些數字合起來說明了什麼、和昨天或市場預期比如何、對台美市場的含意。
- 每個區塊結尾要有「所以呢」：AI 判斷、信心、接下來要看什麼。
- 多條新聞或數據指向同一件事時，要歸納成一個結論，不要逐條平鋪。
- 意見分歧時（例如法人看多看空都有），寫出雙方論點，再說 AI 比較認同哪一邊、為什麼。

### 6.3 其他寫作規則

- 報告中分析者一律稱「AI」，不用第一人稱「我」。例如「AI 認為」「AI 判斷」「市場怎麼看 vs AI 怎麼看」「AI 分析」。

- 每條重點都要有「所以呢」：對哪個市場、往哪個方向、多大程度。
- 數字帶單位與日期；百分比和點數至少給一個。
- 專有名詞第一次出現時簡單說明。
- 不用誇張字眼、不堆形容詞、不用表情符號。
- 漲跌一律標顏色 class。機率旁註明「主觀」。
- 事實與判斷分開寫；判斷要說出理由。

## 七、reports.js 格式與網站首頁

- 網站名稱：**市場日報**。首頁上方是「早報」與「盤後午報」兩張卡，用不同顏色區分（早報深藍、午報赭色），卡片上方有醒目的標籤與日期（各有重點摘要與台美短中長期一行式立場），下方是所有早報與所有午報，左右各一半。首頁簡短寫明資料截止與上線時間：早報「平日｜資料截至 07:00，約 07:30 上線｜全市場，最完整」；盤後午報「平日｜資料截至 15:30，約 16:00 上線｜全市場，以台股為主」。首頁卡片的立場行：早報卡顯示台灣、美國各自的短中長期；午報卡只顯示台股短期（由 `views` 欄位決定，午報只填 `tw.s`）。首頁清單每列：主題（`headline`）一行，太長自動截斷，滑鼠移過顯示全文；下方小字是立場（早報顯示台、美短期，午報顯示台股短期）。首頁不放 Analytics Hub 連結。首頁標頭右下有小字連結「分析 Prompt 說明」，指向 `method.html`；該頁會直接讀取 `RULES.md` 與 `RULES-PM.md` 顯示，所以規則改了就自動同步，不用另外改頁面。
- 早報檔名 `reports/YYYY-MM-DD.html`，`kind: "am"`；午報檔名 `reports/YYYY-MM-DD-pm.html`，`kind: "pm"`。上一份／下一份只在同一種之間切換。
- 每筆要有 `points`：3–5 條重點摘要（首頁卡片顯示）。

### reports.js 欄位

```js
{
  id: "2026-11-16", kind: "am", date: "2026-11-16", weekday: "一" /* 中文 */, edition: "早報",
  points: ["重點一", "重點二", "重點三"],
  headline: "一句話標題",
  summary: "兩到三句摘要",
  views: {
    tw: { s: "lbear", m: "lbear", l: "lbull" },
    us: { s: "...", m: "...", l: "..." }
  },
  stats: "加權 xx｜S&P 500 xx｜費半 xx｜美債 10 年 xx｜新台幣 xx"
}
```

立場代碼：`bull` 偏多、`lbull` 中性偏多、`neutral` 中性、`lbear` 中性偏空、`bear` 偏空。

## 八、view-log.md 格式

檔頭固定一句「每份早報、午報產出後更新，最新的在最上面。」每份早報在最上面加一節，標題固定：

`## YYYY-MM-DD（X）早報（資料截至 07:00；新聞窗口 MM/DD 07:00–MM/DD 07:00）`

內容依序：

1. 立場表（台灣、美國 × 短中長期，含信心；日本、南韓只記短期）
2. 情境機率：台灣、美國各期的樂觀／基本／悲觀，以及總經四種情境（5.6 `mc-scn`）
3. 核心判斷（3–5 條）
4. 關鍵數字（供隔天比較，口徑見 4.7「口徑固定」）
5. 台股止穩訊號狀態
6. 翻轉條件
7. 待追蹤事件（日期、台北時間）
8. 明天要補查的；研究筆記路徑（`_research/YYYY-MM-DD/`）
9. **今天 07:00 之後已知的事件**：寫報告時如果已經是 07:00 以後，把當下已知但不能寫進今天報告的事列在這裡，給午報與隔天早報當線索，使用前仍須重新查證。

當天午報會在這一節的第 9 項前面加上「午報更新」小節（格式見 RULES-PM.md 第七節）。當天沒有早報時，午報另開一節（見 RULES-PM.md 第七節）。

## 九、排程

- **只在週一到週五**的 07:00（台北）由 Claude 桌面版排程任務執行（系統會加幾分鐘延遲）。App 沒開時會在下次開啟時補跑。週六、週日不出報告。
- **報告日期＝觸發排程的那個平日。** 不補做過去的日期：昨天的早報沒出，今天不補，只在今天的報告裡照常和最近一份報告比較。
- **補跑：** 實際執行時已經晚於 07:00，仍以 07:00 為時間界線寫報告；07:00 之後的資訊放進 view-log 第 9 項。補跑開始時已經晚於當天 15:30，就不產出這份早報（當天交給午報），在回報裡寫明「早報略過」。
- **和午報同時執行：** 開始前照步驟 0 第 3 項檢查，commit 時只帶自己的檔案，rebase 衝突照步驟 6 處理。
- 週一的報告要涵蓋整個週末：新聞窗口從上週五 07:00 起算，總覽要有「週末發生了什麼」，並加上本週展望。
- 平日遇到台灣或其他市場休市照常產出，休市的市場行情標明為上一交易日（判斷方法見 4.7「休市判斷」）。
- **過渡說明：** 11/16 早報是特例，以 11/16 08:00 為時間界線。11/17 早報起一律 07:00；11/17 的新聞窗口從 11/16 07:00 起，和 11/16 早報重疊的 07:00–08:00 這段靠去重清單處理。
