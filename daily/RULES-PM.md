# 市場日報｜盤後午報：分析方向與報告標準

這份是**盤後午報**的完整規則。每次產出或修改午報前都要從頭到尾讀完，照這份做。
午報和早報共用同一套網站與寫作標準；共用的部分本檔會寫明「照 RULES.md 第幾節」，那些章節也必須讀。

---

## 〇、要讀哪些檔案（必做）

1. **本檔全文。**
2. **`daily/RULES.md` 的以下章節**（午報同樣適用）：
   - 一、最高原則（第 2–7、9、10 條。第 1 條的時間界線與第 8 條的新聞窗口，午報改用本檔第二節）
   - 4.3 立場、信心與機率；4.4 利空利多分類；4.5 台灣檢查表；4.6 常見錯誤
   - **4.7 分析方法細則**（估值、均線、缺口、回吐比例、籌碼解讀、去槓桿與轉空的判斷、情境機率、可信度、時區）
   - **4.8 交稿前自我檢核**
   - 5.1 版面原則（摘要三層、小標題、配色）；5.5 專題格式（午報專題選用）；5.8 新聞卡片格式；**5.9 HTML 與 class 規格**（含 `<head>` 圖示與 manifest、手機表格、註解標籤）
   - 六、寫作標準（6.1 摘要長度、6.2 分析與歸納、6.3 用語「AI」）
3. **當天的早報**（`daily/reports/YYYY-MM-DD.html`）：午報要接續它的台股觀點與翻轉條件。
4. **`daily/state/view-log.md`** 最上面一節（當天早報的紀錄）。
5. **最近一份午報**（`daily/reports/*-pm.html`）：完全沿用它的 HTML 結構與 class。

**不適用午報的早報規則：** 07:00 時間界線、24 小時新聞窗口、早報的主分頁結構（個別市場、總經、行事曆）、台美同等權重。午報以台股為主。

---

## 一、定位

- **讀者在台股收盤後閱讀。** 要回答三件事：今天台股發生了什麼、為什麼、明天與這週要注意什麼。
- **聚焦台股。** 其他市場只寫日、韓、中的收盤與重大事件，以及全球重大事件（不限國家），每項都寫對台股的含意。
- **比早報精簡，但不能只丟資訊。** 每一段、每張表後面都要有歸納和判斷（RULES.md 6.2）。
- **接續早報。** 午報的核心是「觀點更新」：今天的走勢驗證了早報哪些判斷、推翻了哪些，台股短期觀點要不要調整。

---

## 二、時間界線與資料範圍

- **時間界線：當天台北 15:30。** 只能用 15:30 以前已公開的資訊。即使實際執行時已晚於 15:30，也以 15:30 為準；之後才公布的資料寫進 view-log，留給隔天早報。
- **新聞窗口：當天台北 07:00 到 15:30。** 每則新聞都要確認發布時間。當天早報已寫過的事件，只寫新的發展。
- 只在週一到週五、台股有開市的日子出午報；台股休市就不出，直接回報。

### 2.1 15:30 時可以用的資料

| 資料 | 一般公布時間（台北） | 說明 |
| --- | --- | --- |
| 加權、櫃買、類股指數、漲跌家數、個股收盤 | 13:30 收盤後 | 證交所 FMTQIK、MI_INDEX |
| 台指期日盤收盤、結算價、未沖銷量 | 13:45 收盤後 | 期交所 futDailyMarketReport |
| 三大法人買賣金額（BFI82U） | 約 15:00 前後 | **15:30 時是初版**，晚間可能修正。午報用初版並在表格註明「證交所 15:30 前初版」；隔天早報改用修正版並說明 |
| 三大法人期貨未平倉（futContractsDate） | 約 15:00 後 | 寫成「期交所約 15:00 公布」 |
| 日股、韓股收盤 | 14:30 | |
| A 股收盤 | 15:00 | |
| 當天 07:00–15:30 的新聞、官員發言、數據 | — | 每則確認發布時間 |

### 2.2 15:30 時通常還沒有的資料（不要寫）

- 外資個股買賣超明細（約 16:00 後）
- 選擇權 P/C 比（公布時間無法確認，**除非查核時確認 15:30 前已公布，否則不寫**）
- 融資融券、維持率（晚間）
- 新台幣收盤（16:00）；盤中匯價只有在有 15:30 前的報導時才能引用，並註明是盤中
- 港股收盤（16:00 後）、歐美盤勢、台指期夜盤
- 15:30 後才發布的新聞稿（即使內容是當天的事）

## 三、作業流程

1. 讀第〇節列的所有檔案。確認今天是平日且台股有開市。
2. **蒐集資料**（開 2 個研究子代理平行進行；研究筆記另存到 `C:\Users\User\Desktop\news\_research\YYYY-MM-DD\`，檔名用 `-pm` 結尾）：
   - **台股子代理：** 證交所 FMTQIK（當月與前 12 個月，用來自算均線）、MI_INDEX（`type=IND` 類股、`type=MS` 漲跌家數、各產業別取個股收盤）、BFI82U（三大法人）；期交所行情、三大法人期貨；當天官員、央行、金管會、國安基金的發言；投顧與法人觀點。每個數字附來源與公布時間。
   - **新聞子代理：** 07:00–15:30 的重點新聞（格式見 5.8），每則確認發布時間（台北），並列出「時間窗外沒收」的稿件。台股新聞最多；其他市場只收重大事件；全球重大事件不限國家。
   - 指示子代理：所有內容來自搜尋與官方資料，不可用記憶；查不到寫查無；絕不編造數字或連結。
3. **分析**（第四節）並**寫報告**（第五節）。
4. **查核（必做）：** 開獨立的查核子代理，給它報告路徑與研究筆記路徑，要求它：
   - 直接抓證交所、期交所原始資料，核對所有台股數字、均線（自己重算）與百分比
   - 核對日、韓、中收盤與個股漲跌
   - 檢查 15:30 時間界線：每項官方資料在 15:30 是否已公布、每則新聞是否在 07:00–15:30
   - 核對官員發言、媒體引述與原文是否一致
   - 驗算情境機率加總 100%
   - 回報：錯誤（必改）、越過時間界線（必改）、無法確認（加註或刪除）
   依清單修正後才能發布。
5. **更新索引與紀錄：**
   - `daily/reports.js` 最前面加一筆（格式見第六節）。
   - `daily/state/view-log.md`：在當天早報那一節的「9. 之後已知事件」前面，加「午報更新」小節（格式見第七節）。
6. **發布：** 在 `/c/Users/User/Desktop/news` 依序執行 `git add daily`、`git commit -m "daily: YYYY-MM-DD 盤後午報"`、`git pull --rebase origin main`、`git push origin main`。推送後等 1–2 分鐘，用 curl 確認 `https://finatticus.github.io/structuredproductanalysis/daily/reports/YYYY-MM-DD-pm.html` 回應 200。
7. **回報** 5 行以內：一句話定性今天台股、短期觀點是否調整、報告連結、查核修正了幾處、仍無法確認的資料。

## 四、分析方向

計算與判斷方法一律照 RULES.md 4.7；交稿前照 RULES.md 4.8 與本節最後的「午報自我檢核」。報告中分析者一律稱「AI」。

### 4.1 盤勢歸納

- **一句話定性今天：** 例如「恐慌性下殺」「技術性反彈」「量縮整理」「權值股撐盤、中小型股弱」。
- **拆解漲跌來源：** 台積電與主要權值股的貢獻；電子與非電子（`未含電子` 指數）、大型與中小型的差異。
- **型態與量：** 開高走低或開低走高、收在全天高低點的哪裡、成交量和前幾天比（用證交所總計口徑比較，並寫明口徑）。
- **族群輪動：** 哪些族群逆勢、哪些重挫；它們是被同一件事驅動，還是不同事件。
- **歸納：** 用一段話把以上合成一個判斷（例如「賣的是 AI 硬體曝險，不是台灣整體」）。

### 4.2 籌碼解讀

- 外資、投信、自營商（區分自行買賣與避險）的方向與規模，和前幾天比；投信、外資的連續買賣超天數。
- 外資台指期淨未平倉的變化（大跌時有沒有加空）；投信期貨多單多為 ETF 避險。
- 結算週：近月與次月未平倉分布、逆價差（用最後成交價與結算價各算一次）。
- **歸納：** 今天的賣壓或買盤主要來自誰？屬於恐慌、去槓桿、避險，還是看法轉變？判斷方法照 RULES.md 4.7「去槓桿或轉空」。

### 4.3 技術面與關鍵價位

- 自算均線（5、10、20、60、120、240 日，含今天收盤），列表寫出數值與指數相對位置，說明今天站上或跌破哪一條。
- 缺口（今天是否留下新缺口、是否回補舊缺口）、前波高低點、整數關卡、回吐比例。
- 關鍵價位表：明天的壓力與支撐，每個都寫意義與距今天收盤的百分比。

### 4.4 消息與政策

- 當天官員、央行、金管會、國安基金、財政部的發言：用表格列「時間（台北）、發言或事件、AI 的解讀」。
- 重要公司消息、法說、營收；投顧與法人觀點（看多看空都要列，並寫 AI 比較認同哪一邊）。

### 4.5 觀點更新（午報的核心）

- **和早報對照：** 用表格列「早報的判斷、今天的結果、評估」，至少涵蓋：早報的短期方向、關鍵支撐壓力、情境、翻轉條件是否觸發。
- **短期立場：** 依早報寫好的翻轉條件判斷是否改變立場（不能事後找理由）。寫明維持、上修或下修與原因。
- **短期情境表：** 更新條件、可能區間與主觀機率（加總 100%），附機率條與新的翻轉條件。
- **中長期：** 原則上留給隔天早報；只有今天發生改變中長期判斷的事件才寫。
- **明天開盤要看什麼：** 表格列「時間（台北）、事件、偏多的情況、偏空的情況」，通常包括：今晚公布的融資餘額、今晚美股與費半、台積電 ADR、明天 05:00 夜盤收盤、重要數據與財報、結算日。
- 必要時更新早報的「止穩訊號」（或過熱訊號）清單的狀態。

### 4.6 其他市場（簡要）

- 日經、TOPIX、KOSPI（及 KOSDAQ）、上證、創業板、科創 50 的收盤與漲跌；主要個股（愛德萬、東京威力、軟銀、SK 海力士、三星等）。
- 當天公布的重要數據（例如中國月度數據、日本 GDP）。
- 全球重大事件（不限國家）。每項都寫對台股的含意，最後用一段話歸納亞洲盤勢和台股的關係。

### 4.7 專題（選用）

- 當天有值得深挖、會影響之後判斷的事件才放（例如單日重挫的性質、重大政策、權值股法說、央行意外動作）。沒有就不放，不要硬湊。
- 格式照 RULES.md 5.5：專題摘要、至少 2 個視覺輔助（時間線、長條圖、證據天平等）、`div.essay` 深入分析 4–6 段、市場怎麼看 vs AI 怎麼看、證據表、觀察清單。

### 4.8 午報自我檢核（交稿前）

- 有沒有用到 15:30 以後才公布的資料（特別是外資個股、融資、新台幣收盤、P/C 比、港股收盤）。
- 三大法人數字是否註明「15:30 前初版」。
- 每則新聞是否在 07:00–15:30、是否和當天早報重複。
- 均線是否自己重算、百分比是否驗算過。
- 是否和早報的觀點與翻轉條件對照過，立場與情境機率是否一致。
- 每張表後面是否有歸納；用語是否統一為「AI」。
- `<head>` 是否有圖示與 manifest；每張表是否有 `thead`；375px 寬度下頁面不能左右捲動。

## 五、版面

檔案 `daily/reports/YYYY-MM-DD-pm.html`，`<body data-report="YYYY-MM-DD-pm">`，共用 `../assets/report.css`、`../assets/report.js`、`../reports.js`。`<head>` 照 RULES.md 5.9（含圖示與 manifest）。
刊頭：kicker 寫「市場日報 · 盤後午報 · YYYY-MM-DD 星期」，標題一句話定性今天，meta 寫「資料截至台北時間 MM/DD（X）15:30」「台股：今日收盤」「日韓中：今日收盤」。右上按鈕：「← 前一份午報」「首頁」「後一份午報 →」。

### 5.1 主分頁（固定順序與 id）

| 順序 | id | 名稱 | 內容 |
| --- | --- | --- | --- |
| 1 | `pm-overview` | 總覽 | 第一層摘要（一句粗體定性＋ 5–7 條：盤勢、為什麼跌或漲、籌碼、不同於表面的訊號、技術面、觀點更新、明天要看）；數據列（加權、成交金額、三大法人、外資台指期淨空、台指期、漲跌家數）；短期觀點一行（早報 vs 午報立場標籤＋「維持／上修／下修」）；明天開盤前要看的三件事（`ol.keys`） |
| 2 | `pm-theme` | 專題（選用） | 見 4.7 |
| 3 | `pm-tw` | 台股盤後 | 第一層摘要；子分頁 `pm-mkt` 盤勢（類股表、權值股表、歸納 callout）、`pm-chips` 籌碼（三大法人表、期貨表、歸納 callout）、`pm-tech` 技術與價位（均線表、關鍵價位表）、`pm-policy` 消息與政策（時間、發言、解讀表） |
| 4 | `pm-view` | 觀點更新 | 第一層摘要；和早報的對照表；短期立場標題列（`div.vhead`）、情境表、機率條、翻轉條件 callout；明天開盤要看什麼表 |
| 5 | `pm-other` | 其他市場 | 第一層摘要；日韓中收盤表（每列寫對台股的含意）；重大事件表 |
| 6 | `pm-news` | 新聞 | 第一層摘要（含歸納）；篩選列 `.fbar`（全部／台灣／美國／全球，當天有日本、南韓新聞時加上日本／南韓）；新聞卡片照 RULES.md 5.8 |

每個分頁與子分頁最上方都要有摘要（RULES.md 6.1，子分頁 4–6 句），三層外觀照 RULES.md 5.1。

## 七、view-log.md「午報更新」小節格式

```markdown
### 午報更新（MM/DD 15:30）

- 台股短期：維持／上修／下修為 ○○（信心），情境：…（三個情境與機率）
- 原因：對照早報翻轉條件的結果
- 自算均線（MM/DD）：5 日／10 日／20 日／60 日／120 日／240 日；新缺口
- 新的翻轉條件
- 注意：15:30 後才公布或修正的資料（例如三大法人修正版、融資），隔天早報要補上或改用
- 隔天早報要接續的事
```
