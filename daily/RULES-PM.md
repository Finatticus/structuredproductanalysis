# 市場日報｜盤後午報：分析方向與報告標準

這份是**盤後午報**的完整規則。每次產出或修改午報前都要從頭到尾讀完，照這份做。
午報和早報共用同一套網站與寫作標準；共用的部分本檔會寫明「照 RULES.md 第幾節」，那些章節也必須讀。

**規則怎麼改：** 只和午報有關的規則改在本檔，並在 `daily/state/changelog.md` 加一行修訂紀錄。網站共用規格（版面、class、首頁、寫作標準、口徑）只寫在 `RULES.md`，本檔只引用，不另寫一份，避免兩邊不一致。

   - 一、最高原則（第 2–7、9、10 條。第 1 條的時間界線與第 8 條的新聞窗口，午報改用本檔第二節）
   - 三、步驟 1 的「台灣官方資料網址」與「來源優先順序」兩段（「三大法人用修正後的數字」是早報規則，午報不照做）
   - 4.1 時間尺度；4.3 立場、信心與機率（含比較基準）；4.4 利空利多分類；4.5 台灣檢查表；4.6 常見錯誤
   - **4.7 分析方法細則**（估值、均線、缺口、回吐比例、籌碼解讀、去槓桿與轉空的判斷、情境機率、可信度、**口徑固定**、**休市判斷**、時區）

   - 5.1 版面原則（摘要三層、小標題、配色）；5.5 專題格式與個股圖表工具（午報個股專題用）；5.8 新聞卡片格式與篩選值；**5.9 HTML 與 class 規格**（含 `<head>` 圖示與 manifest、範本清理、手機表格與檢查方法、註解標籤）
   - 六、寫作標準（6.1 摘要長度、6.2 分析與歸納、6.3 用語「AI」）
3. **`daily/state/view-log.md`** 最上面一節（通常是當天早報的紀錄）；另外查最近 10 個交易日「午報更新」裡的個股專題紀錄，避免重複選股（4.7）。
4. **當天的早報**（`daily/reports/YYYY-MM-DD.html`）：午報要接續它的台股觀點與翻轉條件，新聞要和它去重；個股專題不能選它專題（`th-*`）的主角公司。
5. **最近一份午報**（`daily/reports/` 裡最新的 `*-pm.html`）：它是版型範本，完全沿用它的 HTML 結構與 class。

### 0.2 前置檢查

1. 用系統時間確認今天日期、星期與現在時間。報告日期 D ＝ 觸發排程的那個平日（第八節）。**現在早於 15:20，代表是前一天漏跑的補跑：不產出，回報「午報略過（補跑時間不對）」。**（15:20–15:30 之間開始的，照常產出，時間界線仍是 15:30。）
2. 確認 D 台股有開市（RULES.md 4.7「休市判斷」）；休市就不出午報，直接回報「台股休市，午報略過」。
3. **上鎖：** 在 `C:\Users\User\Desktop\news` 執行 `python daily/tools/runlock.py acquire pm`。印出 BUSY 代表早報還在執行：改跑 `python daily/tools/runlock.py wait pm`（每次最多等 9 分鐘），最多 5 次；還是 BUSY 就停止並回報。上鎖後，之後不論發布成功或中途停止，最後都要執行 `python daily/tools/runlock.py release pm`。
   接著 `git status`，再 `git pull --rebase --autostash origin main`。
   - `daily/reports/D-pm.html` 已存在、或 `reports.js` 已有 D 的午報：停止，回報「已產出」。
   - `reports.js` 或 `view-log.md` 有不是自己改的未 commit 改動：代表早報可能還在產出。不要覆寫，commit 時也不要帶進去。
4. **當天沒有早報時**（早報沒出或還沒推送）：以最近一份早報＋其後的午報與 view-log 為起點；「觀點更新」分頁改成對照最近一份早報，並在摘要寫明「當天無早報，對照 MM/DD 早報」。view-log 的寫法見第七節。

## 一、定位

- **讀者在台股收盤後閱讀。** 要回答三件事：今天台股發生了什麼、為什麼、明天與這週要注意什麼。
- **聚焦台股。** 其他市場只寫日、韓、中的收盤與重大事件，以及全球重大事件（不限國家），每項都寫對台股的含意。
- **比早報精簡，但不能只丟資訊。** 每一段、每張表後面都要有歸納和判斷（RULES.md 6.2）。
- **接續早報。** 午報的核心是「觀點更新」：今天的走勢驗證了早報哪些判斷、推翻了哪些，台股短期觀點要不要調整。
- **個股專題。** 午報的專題固定是台股、美股各一檔的個股深度分析（4.7），不寫事件型專題，避免和早報重複。

## 二、時間界線與資料範圍

- **時間界線：當天台北 15:30。** 只能用 15:30 以前已公開的資訊（例外：2.2 列的幾項照 2.2 判斷）。即使實際執行時已晚於 15:30，也以 15:30 為準；之後才公布的資料寫進 view-log，留給隔天早報。
- **新聞窗口：當天台北 07:00 到 15:30。** 每則新聞都要確認發布時間。
- **新聞去重：** 去重清單＝當天早報的所有新聞標題（`span.n-t`）。早報已寫過的事件，只有在 07:00 之後有新發展時才收，而且只寫新的發展。

### 2.1 15:30 時可以用的資料

| 資料 | 一般公布時間（台北） | 說明 |
| --- | --- | --- |
| 加權、櫃買、類股指數、漲跌家數、個股收盤 | 13:30 收盤後 | 證交所 FMTQIK、MI_INDEX（`type=IND`、`type=MS`），網址見 RULES.md 步驟 1 |
| 台指期日盤收盤、結算價、未沖銷量 | 13:45 收盤後 | 期交所 futDailyMarketReport（交易時段選一般） |
| 三大法人買賣金額（BFI82U，`type=day&dayDate=YYYYMMDD`） | 約 15:00 前後 | **15:30 時是初版**（不含鉅額交易等之後才併入的部分），晚間可能修正。午報用初版並在表格註明「證交所 15:30 前初版」；隔天早報改用修正版並說明 |
| 成交金額 | 13:30 收盤後 | 15:30 時抓到的是當時的數字，晚間可能因盤後交易併入而變大；午報照抓到的寫，隔天早報用最終值並註明 |
| 三大法人期貨未平倉（futContractsDate） | 約 15:00 後 | 寫成「期交所約 15:00 公布」；外資淨未平倉口徑照 RULES.md 4.7「口徑固定」 |
| 日股、韓股收盤 | 14:30 | |
| A 股收盤 | 15:00 | |
| 當天 07:00–15:30 的新聞、官員發言、數據 | — | 每則確認發布時間 |

每次抓官方資料都要確認回傳的日期是今天（當天資料還沒公布時，API 可能回傳前一交易日）。

**抓不到就寫明：** 表上的公布時間只是參考。開始寫報告時直接抓；某項資料還沒公布（例如三大法人），就在報告該處寫明「15:30 時尚未公布」，不要等，也不要用其他日期的數字代替。

### 2.2 15:30 時通常還沒有的資料（本節是唯一標準，其他段落都照這裡）

- 外資個股買賣超（TWT38U）、選擇權 P/C 比、融資融券與維持率、新台幣收盤（16:00）、港股收盤（16:00 後）。
- **可以用的條件：** 腳本檔頭的抓取時間在 16:00 以前，而且官方已經有當天的資料（腳本沒有寫「尚未公布」）。用的時候註明資料日期。
- **其他情況**（腳本寫尚未公布、這幾項抓取失敗，或開始時已晚於 16:00 的補跑）：一律寫「15:30 時尚未公布」，不要等，也不要用其他日期代替。
- 查核員事後重跑腳本時拿到這些資料，不代表主筆漏寫，不算錯誤。
- 新台幣盤中匯價只有在 15:30 前的報導裡才能引用，並註明是盤中。
- 歐美盤勢、美股期貨、台指期夜盤不寫。
- 15:30 之後才發布的新聞稿不收，即使內容是當天的事。

## 三、作業流程

1. **開始前：** 做完第〇節（讀檔、前置檢查）。
2. **先跑腳本（約 3 分鐘，官方數字一律以腳本輸出為準）：**

   ```bash
   cd /c/Users/User/Desktop/news
   python daily/tools/twdata.py market D --cutoff "D 15:30" --out _research/D   # 台股大盤、類股、成交金額前 20 名、三大法人（含連續天數與月累計）、期貨；外資個股、P/C、融資照 2.2
   python daily/tools/usdata.py quotes --cutoff "D 15:30" --out _research/D     # 日韓中收盤、日韓重點個股、美股 AI 與大型科技股（選股參考）、匯率、商品（美股期貨不寫）
   ```

   - 一律用 Bash 工具，在背景執行或把 timeout 設成 600000。同一時間只跑一支 twdata.py（證交所有頻率限制），usdata.py 可以同時跑。腳本寫「尚未公布」的項目照寫（2.1「抓不到就寫明」），不要另外找替代數字；寫「抓取失敗」或「腳本錯誤」的，要手動到官方網站確認後再寫（2.2 列的幾項除外，照 2.2）。
   - 加權指數均線、成交值、法人、期貨未平倉都直接用腳本的數字，不要再手動抓或請子代理抓。
3. **開研究子代理、選兩檔個股（在背景平行進行）：** 台股子代理、新聞子代理在第 2 步一開始就和腳本同時啟動；兩個個股子代理在選股後啟動。
   - **選股：** 用腳本輸出的成交金額前 20 名與漲跌幅（3b 節）、類股漲跌、前一交易日的法人動向，加上 `usdata.py quotes` 的美股個股漲跌，再快速搜尋一兩次當天焦點，5 分鐘內決定（4.7 的選股與去重）。台股優先選上市股票（腳本只支援上市）；選上櫃股要手動抓櫃買中心資料並確認資料時間，抓不到就換一檔。
   - **選定後馬上跑個股腳本（約 2 分鐘）：**

     ```bash
     python daily/tools/twdata.py stock 代號 D --chips-until prev --out _research/D
     python daily/tools/usdata.py stock 代號 --cutoff "D 15:30" --out _research/D
     python daily/tools/usdata.py fund 代號 --cutoff "D 15:30" --out _research/D   # SEC：近 8 季 GAAP 財報、近 90 天 Form 4（含加權平均價）
     ```

     產出 `px-tw-代號.csv`、`px-us-代號.csv`（給 stockviz.py 用），以及個股的法人、融資、本益比、外資持股、和 Nasdaq 交叉比對過的股價。
   - **研究子代理（4 個，平行）：** 研究筆記固定放在 `C:\Users\User\Desktop\news\_research\YYYY-MM-DD\`，檔名 `tw-pm.md`、`news-pm.md`、`stock-tw-pm.md`、`stock-us-pm.md`。**腳本已經抓的資料不要再抓**，指示裡要附上腳本輸出檔的路徑。
     - **台股子代理：** 只找腳本抓不到的：盤勢原因與族群輪動的報導（族群強弱對照腳本第 3 節完整排序）、當天官員、央行、金管會、國安基金的發言、投顧與法人觀點、重要公司消息、15:30 前報導的新台幣盤中匯價（註明時間）、日韓中的重大事件與重點個股；TOPIX、創業板、科創 50、深證成指、滬深 300 的收盤與漲跌（腳本沒有）。
     - **新聞子代理：** 07:00–15:30 的重點新聞（格式見 RULES.md 5.8），每則確認發布時間（台北），並列出「時間窗外沒收」的稿件。主筆要把當天早報的新聞標題清單交給它去重。台股新聞最多；其他市場只收重大事件；全球重大事件不限國家。
     - **台股個股子代理：** 依 4.7「內容」1–7 蒐集公司介紹、業務、營收結構、月營收、季報、法說重點與展望、券商目標價、近期新聞與催化劑。股價、法人、融資、本益比用腳本輸出，不要再抓。
     - **美股個股子代理：** 依 4.7「內容」1–7 蒐集；GAAP 財報與內部人交易先用 `usdata.py fund` 的輸出（已確認收件時間），子代理補 non-GAAP 數字、財測、法說重點、機構持股與 13F（逐份確認 EDGAR 收件時間在界線前）、空單比率、券商目標價（都寫資料日期）。客戶集中度要分清楚「直接客戶（經銷商）」和「終端客戶」，並寫期間。股價用腳本輸出，不要再抓。
     - 四個子代理的指示都要寫：今天日期、15:30 時間界線、所有內容來自搜尋與官方資料，不可用記憶；查不到寫查無；絕不編造數字或連結；來源優先順序照 RULES.md 步驟 1；先讀 `daily/state/lessons.md` 裡和研究有關的教訓。
     - **筆記要精簡：** 以表格為主，每列附來源與日期，不寫長篇敘述。台股子代理約 12,000 字、25 次搜尋；新聞子代理約 20,000 字、40 次搜尋；兩個個股子代理各約 20,000 字、30–40 次搜尋（個股要寫得很詳細，4.7「內容」1–7 每項都要有資料才算完成）。字數一律以字元計（含表格與網址）；打開網頁確認原文不算在搜尋次數裡。
     - **個股子代理直接交 HTML（加快速度）：** 兩個個股子代理除了筆記，還要交整個子分頁（`st-tw`、`st-us`，含五個第三層子分頁）的 HTML 草稿，圖表自己用 stockviz.py 產生，class 照最近一份午報。新聞子代理也交新聞卡片 HTML。主筆不重寫片段，只負責整合、寫總摘要、改錯，以及檢查前後一致。
     - 台股、新聞子代理不用等腳本跑完：指示裡先寫好腳本輸出檔的路徑，和腳本同時啟動。
4. **一邊等子代理，一邊寫（不要空等）：**
   - 用 `python daily/tools/newreport.py pm D` 建立骨架（自動換好日期、標題列、頁尾，要改的地方標「【待填】」「【待確認】」），再照 RULES.md 5.9「範本清理」逐段改寫（個股專題整段換成新的兩檔，不可留下前一份的公司內容）。
   - 總覽數據列用 `python daily/tools/snapshot.py pm-kpis --tw _research/D/official-tw-YYYYMMDD.md` 直接產生。
   - 先寫只靠腳本就能完成的部分：總覽數據列、台股盤後的類股表（含櫃買指數，比較大型與中小型股）、法人表、期貨表、均線與關鍵價位表、開高低與缺口（腳本第 1b 節）、權值股貢獻點數（第 11 節）。表格用 `python daily/tools/md2html.py 腳本輸出.md "## 4."` 直接轉成 HTML，不要手打數字（顏色只看正負號，像外資淨未平倉這種部位水準，要把 class 改成 `num`）。個股的均線、報酬、52 週高低、走勢圖、目標價區間圖、時間序列圖都由個股子代理用 stockviz.py 產生（RULES.md 5.5），主筆只檢查。
   - 子代理回來後，再寫台股分析、觀點更新與總摘要（第四節）；新聞卡片與 `st-tw`、`st-us` 子分頁整合子代理交的 HTML，只改錯、補總摘要，並檢查前後一致。
   - **寫檔要有效率：** 一次寫好整個分頁或整個段落（用 Python 一次替換，或一次 Edit 一大段），不要一句一句改；只讀需要的段落（Grep 找位置再讀那幾行），不要反覆讀整份 HTML。
5. **更新索引與紀錄（在查核之前）：**
   - `daily/reports.js` 最前面加一筆（格式見第六節）。
   - `daily/state/view-log.md`：在當天早報那一節的「9. 之後已知事件」前面，加「午報更新」小節（格式見第七節）。
6. **查核（必做，不可省略）：** 開獨立的查核子代理。

   **兩個查核員平行進行（比較快）：**
   - **數字查核員：** 核對所有數字。**第一步先跑 `python daily/tools/crosscheck.py 報告.html _research/{D}/official-*.md _research/{D}/stock-*.md`**，它會列出「和官方數字很接近但不一樣」的地方（疑似抄錯），優先處理；這只是篩選，列出來的不一定錯。接著重跑腳本（輸出到 `_research\{D}\verify\`），和報告逐項比對；**和主筆的數字不同時，先比對主筆的 `raw-tools\` 原始檔（台股）或 official-us、stock-us 檔頭的抓取時間（美股）：差異來自官方在截止後修正的（例如成交金額、三大法人修正版），不算錯誤，報告以截止時的版本為準。** 重跑同一支腳本抓不出腳本自己的錯，所以還要挑 5 個以上的關鍵數字用另一個獨立來源（官方網頁、中央社、鉅亨網、通訊社）核對，而且每天至少包含一項容易解析錯的：融資金額單位（仟元）、類股漲跌正負號、櫃買指數與成交金額單位、P/C 比（有用到時）。腳本沒有的數字（總經、財報、目標價）照常回到原始來源核對。
   - **內容查核員：** 新聞（每則卡片逐句核對，見查核項目 6）、引述、時間界線、和前一份的一致性、個股專題的選股與完整性、用語、範本殘留（先跑 `python daily/tools/residue.py 新報告 範本報告`）、reports.js 與 view-log。

   兩個查核員都用下面的範本，各自只做自己那一半的檢查項目。

## 四、分析方向

計算與判斷方法一律照 RULES.md 4.7；交稿前照 RULES.md 4.8 與本節最後的「午報自我檢核」。報告中分析者一律稱「AI」。

### 4.1 盤勢歸納

- **一句話定性今天：** 例如「恐慌性下殺」「技術性反彈」「量縮整理」「權值股撐盤、中小型股弱」。
- **拆解漲跌來源：** 台積電與主要權值股的貢獻；電子與非電子（`未含電子` 指數）、大型與中小型的差異。
- **型態與量：** 開高走低或開低走高、收在全天高低點的哪裡、成交量和前幾天比（成交值口徑照 RULES.md 4.7「口徑固定」，並寫明）。
- **族群輪動：** 哪些族群逆勢、哪些重挫；它們是被同一件事驅動，還是不同事件。
- **歸納：** 用一段話把以上合成一個判斷（例如「賣的是 AI 硬體曝險，不是台灣整體」）。

### 4.2 籌碼解讀

- 外資、投信、自營商（區分自行買賣與避險）的方向與規模，和前幾天比；投信、外資的連續買賣超天數。
- 外資台指期淨未平倉的變化（大跌時有沒有加空）；投信期貨多單多為 ETF 避險。
- 結算週：近月與次月未平倉分布、逆價差（用最後成交價與結算價各算一次）。
- **歸納：** 今天的賣壓或買盤主要來自誰？屬於恐慌、去槓桿、避險，還是看法轉變？判斷方法照 RULES.md 4.7「去槓桿或轉空」。

### 4.3 技術面與關鍵價位

- 自算均線（5、10、20、60、120、240 日，含今天收盤），列表寫出數值與指數相對位置，說明今天站上或跌破哪一條。
- 缺口（今天是否留下新缺口、是否回補舊缺口）、前波高低點、整數關卡、回吐比例。
- 關鍵價位表：明天的壓力與支撐，每個都寫意義與距今天收盤的百分比。

### 4.4 消息與政策

- 當天官員、央行、金管會、國安基金、財政部的發言：用表格列「時間（台北）、發言或事件、AI 的解讀」。
- 重要公司消息、法說、營收；投顧與法人觀點（看多看空都要列，並寫 AI 比較認同哪一邊）。

### 4.5 觀點更新（午報的核心）

- **和早報對照：** 用表格列「早報的判斷、今天的結果、評估」，至少涵蓋：早報的短期方向、關鍵支撐壓力、情境、翻轉條件是否觸發。
- **短期立場：** 依早報寫好的翻轉條件判斷是否改變立場（不能事後找理由）。寫明維持、上修或下修與原因，比較對象是當天早報（當天無早報時寫明對照哪一份）。價格條件單獨就能觸發；新寫的翻轉條件照 RULES.md 4.3（價格單獨觸發、籌碼條件對應當下的賣壓來源）。
- **短期情境表：** 更新條件、可能區間與主觀機率（加總 100%），附機率條與新的翻轉條件。今天收盤已跌破（突破）早報的情境區間、或悲觀（樂觀）情境已實現時，照 RULES.md 4.7「情境重設」以今天收盤重新設定三個情境，不從早報的數字小調；止穩訊號成立少於 2 項時，最高機率的情境不可以是「區間震盪／打底」（4.7「主情境的限制」）。
- **中長期：** 原則上留給隔天早報；只有今天發生改變中長期判斷的事件才寫。
- **明天開盤要看什麼：** 表格列「時間（台北）、事件、偏多的情況、偏空的情況」，通常包括：今晚公布的融資餘額、今晚美股與費半、台積電 ADR、明天 05:00 夜盤收盤、重要數據與財報、結算日。
- 必要時更新早報的「止穩訊號」（或過熱訊號）清單的狀態。

### 4.6 其他市場（簡要）

- 日經、TOPIX、KOSPI（及 KOSDAQ）、上證、創業板、科創 50 的收盤與漲跌；主要個股（愛德萬、東京威力、軟銀、SK 海力士、三星等）。
- 當天公布的重要數據（例如中國月度數據、日本 GDP）。
- 全球重大事件（不限國家）。每項都寫對台股的含意，最後用一段話歸納亞洲盤勢和台股的關係。

### 4.7 個股專題（每天必做：台股一檔、美股一檔）

午報的新聞窗口只有 07:00–15:30，事件型專題很容易和早報重複，所以午報的專題固定是**個股專題**：每天挑台股、美股各一檔近期關注度高的公司，做非常詳細的個股分析，越詳盡越好。事件分析留給早報的專題。

**選股**
- 關注度的判斷依據（至少符合一項，並在專題摘要寫出選它的理由）：當天或最近幾個交易日漲跌幅或成交值居前；剛公布或即將公布財報、法說、月營收；有重大新聞（合約、產品、政策、經營層異動）；券商大幅調整評等或目標價；對大盤或台股供應鏈影響大。
- 台股可以選上市或上櫃（上櫃的官方資料改用櫃買中心）；美股選在美國上市的公司（含 ADR）。
- **去重：** 不選當天早報專題（`th-*` 子分頁）的主角公司；最近 10 個交易日的午報個股專題已寫過的公司不再選（從 view-log 的「午報更新」查，第七節）。真的非寫不可（例如財報當天），要在摘要寫明理由，內容只寫和上次不同的部分。
- 兩檔之間最好有關聯（例如美股客戶與台股供應商），但不是必要條件。

**資料時間（15:30 界線照第二節）**
- 台股個股：當天收盤可用。個股三大法人買賣超（T86）、融資融券（MI_MARGN）、外資持股比率在 15:30 時還沒有當天資料，只能用到前一交易日，表格要註明「至 MM/DD」。
- 美股個股：用最近一個美股收盤（台北 15:30 時美股盤前還沒開始）。
- 財報數字以公司公告（公開資訊觀測站、SEC、公司投資人關係網站）為準；媒體數字只能當佐證。
- 目標價：只收 15:30 以前公開的，每家都要寫券商、評等、目標價、日期與來源；共識數字要寫資料商與日期，自己平均的標「AI 自算」。

**內容（每檔都要有，缺一不可；查不到的寫「查無」）**
1. **公司介紹：** 成立、經營者、總部、定位與產業地位；主要產品、主要客戶、競爭對手；和台灣或美國供應鏈的關係。
2. **公司業務：** 事業部或產品線的營收占比與趨勢（營收結構圖）；成長動能來自哪裡；近期重大合約、新產品、產能。
3. **基本面：** 最近 6–8 季營收、毛利率、營益率、淨利、EPS 表（台股另列最近 13 個月月營收與年增率）；最新一季財報重點與公司對下一季的財測或展望；估值（本益比、股價淨值比、殖利率或預估本益比）和自己的歷史區間、同業比；AI 的歸納（成長是否加速、獲利品質、估值貴不貴）。
4. **技術面：** 股價走勢圖（收盤＋20、60、120 日線＋成交量，最近約 120 個交易日）；均線表（5、10、20、60、120、240 日，自算）與股價相對位置、均線方向；52 週高低、近 1、3、6 個月與今年以來報酬、RSI、量能；關鍵價位表（壓力、支撐、意義、距收盤百分比）；AI 的歸納（趨勢、型態、超買超賣）。
5. **籌碼面：** 台股：最近 20 個交易日外資、投信、自營商買賣超（長條圖＋表，含累計與連續天數）、融資融券餘額變化、外資持股比率、集保千張大戶比率（查得到才寫）。美股：機構持股比率與主要股東、最新一季 13F 的重要增減、空單比率（寫結算日）、內部人交易、選擇權或 ETF 資金流（有可靠來源才寫）。AI 的歸納（誰在買、誰在賣、籌碼穩不穩）。
6. **市場預期與目標價：** 目標價區間圖；券商評等與目標價表（券商、評等、目標價、日期、理由），最近的上調下調；共識平均、最高、最低與評等分布；平均目標價距現價的空間。
7. **AI 的綜合判斷：** 多方論點與空方論點（各 3–5 點，用 `div.cards2`）；市場怎麼看 vs AI 怎麼看（`div.view-box`）；情境（樂觀、基本、悲觀：條件、可能價格區間、主觀機率加總 100%）；接下來的催化劑與日期（時間線）；觀察清單（`.callout`）。對台股或美股大盤、相關供應鏈的含意寫一段。
- 這是分析，不是投資建議；不要寫「買進」「賣出」之類的建議，立場只寫 AI 對基本面、技術面、籌碼面的判斷。

## 八、排程

- 每個平日 15:30（台北）由 Claude 桌面版排程任務執行；App 沒開時會在下次開啟時補跑。
- **報告日期＝觸發排程的那個平日。** 不補做過去的日期。
- 補跑開始時已經晚於 15:30，仍以 15:30 為時間界線；開始時早於 15:20（前一天漏跑的補跑）或已經過了當天 23:59 就不產出，回報「午報略過」與原因。
- 台股休市日不出午報。
- **排程中不可使用任何會跳出「允許」視窗的工具：** 不可開預覽伺服器（`preview_start`、`.claude/launch.json`）、不可用瀏覽器面板或 Chrome 工具、不可問使用者問題。這些都要人按允許，排程時沒人在，整份報告會卡住（2026-11-18 早報就卡在啟動預覽伺服器）。要看網頁一律用 curl 或 Python 腳本；手機寬度用 `mobilecheck.py`（RULES.md 5.9）。
- 和早報同時執行時，用執行鎖（0.2 第 3 項）避免；commit 與衝突照 RULES.md 步驟 6 處理。
